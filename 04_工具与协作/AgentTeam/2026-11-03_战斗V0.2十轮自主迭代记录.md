# 战斗 V0.2 十轮自主迭代记录

日期：2026-11-03（北京时间）。用户要求连续进行十轮，程序、战斗策划、系统策划按需分工；每轮记录发现的问题、解决的问题、解决方法与实际验证。本记录承接[前一轮受控随机验收](2026-11-03_战斗V0.2受控随机迭代验收.md)，保留其未提交工作区改动。现行规则以[战斗策划案第12章](../../00_Doc/冒牌炼金术士_Demo战斗策划案.md)、[1.5系统](../../00_Doc/协作策划/1.5系统.md)、[1.6数值](../../00_Doc/协作策划/1.6数值.md)为准。轮次中的推演参数不自动成为用户确认的最终玩法。

## 第1/10轮：建立现行碎片供给口径

**发现：** 1.6 第九节的“料/分钟”表仍是旧版整料掉落且要拾取的模型；V0.2 普通怪现为每次击杀15.4%触发碎片、火／露／魔40%／35%／25%分色，同色3碎片才自动成1料。首次使用V0.2的存档开局各1料，后续局原型从0料开始。旧表会高估炼药供给。

**解决及方法：** [1.6数值](../../00_Doc/协作策划/1.6数值.md)已给旧表标明历史口径，并新增5分钟固定配方的多项分布精确推演。以火主＋露辅各3份为例，不计精英、商人、死亡等，假设每分钟普通击杀20／40／60只，首炉在5分钟仍缺料分别为74.37%／5.27%／0.11%；低投各1份的首炉可用。该结果只描述指定配方，不等于所有丹药都不可炼。

**验证：** 制作人以独立的二项边缘与二元多项联合概率计算复核了系统代理的精确求和。尚无真人击杀速度和宝箱拾取率；此轮未改变工程掉率、投料或保底。

复算式：五分钟击杀 `N=5K` 时，令 `pF=0.154×0.40`、`pW=0.154×0.35`、`pO=1-pF-pW`。则 `P(F=f,W=w)=N!/[f!w!(N-f-w)!]×pF^f×pW^w×pO^(N-f-w)`。首次局各1料的指定3+3首炉需 `F≥6,W≥6`；第二炉还需 `F≥15,W≥15`。结果是这两个条件的多项概率求和或补集。

## 第2/10轮：拆分可复现的随机流

**发现：** 原本战斗暴击、刷怪、普通怪碎片和制丹抽样共用一个 `Random`。即使记录了同一开局种子，战斗中多一次随机调用也会改变后续碎片和丹药结果，难以复现最差供给与具体炉次。

**解决及方法：** 程序代理新增 `MaterialRandom` 与 `BrewRandom`，正常局从记录的 run seed 派生并记录两个子种；战斗随机流继续服务刷怪与其他战斗行为。普通怪正常死亡及核弹清怪的碎片触发/分色共用材料流；制丹本体、词条、品质升档使用炼药流。概率、候选权重、扣料规则未改。隔离专项以固定子种证明额外战斗抽样不会改动材料与炼药序列。

**验证：** UE5.8 Editor 编译通过；[60 FPS](../../02_Prototype/AlchemyHD2D/Evidence/BrewV02/60fps-20261103-185014-049-4b32893b/native.log)和[10 FPS](../../02_Prototype/AlchemyHD2D/Evidence/BrewV02/10fps-20261103-185411-591-2a4ed460/native.log)均 `BREW_V02_PASS`。这是隔离原生测试与代码检查，尚未做真人重复局序列回放。

## 第3/10轮：把“多投”解释成战斗用途倾向

**发现：** 原型1／2／3份主材的池内权重分别为 `[6,5,4,3,2]`／`[6,6,6,6,6]`／`[6,7,8,9,10]`。三系索引后的技能职能不同，不能统一声称“多投更强”或“更容易群攻”；原 Q 页虽显示逐项概率，未知技能名遮蔽后仍难判断投料想换来的战斗用途。

**解决及方法：** Q 页从当前运行技能表的施法类型汇总过滤后候选权重，显示“单体／近身范围／落点范围／弹跳”实际用途概率，继续显示逐项概率并隐藏未发现技能名。未改技能池、权重或品质。新增可指定主材和投入份数的[无窗口可视化脚本](../../02_Prototype/AlchemyHD2D/Tools/TestBrewV02Visual.ps1)，只操作隔离截图夹具。

**验证：** Editor 编译通过。魔法主材同一隔离候选集1份→3份，截图中的“弹跳”由64.3%变44.1%、“落点范围”由35.7%变55.9%，与过滤后权重相符；[1份](../../02_Prototype/AlchemyHD2D/Evidence/PC_UI/BrewV02_PC_1280x720_2666749096.png)、[3份](../../02_Prototype/AlchemyHD2D/Evidence/PC_UI/BrewV02_PC_1280x720_26586914.png)。另核对[1024×768火系](../../02_Prototype/AlchemyHD2D/Evidence/PC_UI/BrewV02_PC_1024x768_874171826.png)、[2560×1080露系](../../02_Prototype/AlchemyHD2D/Evidence/PC_UI/BrewV02_PC_2560x1080_1657555533.png)按钮和说明无交叠。用途类别是当前运行表的事实归类，是否帮助玩家做选择仍待真人试玩。

## 第4/10轮：后续局首炉供给试验

**发现：** 后续局从零材料开场，低击杀速度下首炉可能等很久。直接每局开场赠三色各1料，又可通过“开局炼制→接受→重开”零战斗反复解锁永久图鉴。

**解决及方法：** 保留首次 V0.2 开局各1料；后续局暂试“第8个实际死亡的普通怪结算后，每局一次把三色普通材料库存各补到至少1”。已有库存不叠加，碎片计数不清零；精英、Boss入口批量结算、零击杀重开不会触发。此为供真人比较的原型参数，未列为正式保底。

**验证：** Editor 编译通过；[60 FPS](../../02_Prototype/AlchemyHD2D/Evidence/BrewV02/60fps-20261103-193332-354-ddeef669/native.log)和[10 FPS](../../02_Prototype/AlchemyHD2D/Evidence/BrewV02/10fps-20261103-193435-054-dfe96b01/native.log)均 `BREW_V02_PASS`；制作人回归 `PRODUCER_REGRESSION_PASS`，Boss规则 `PLANNED_BOSS_PASS`。原生专项覆盖首局一次性赠料、零击杀重开、第7/8/9次真实普通死亡、已有库存和碎片保留。系统审查发现赠料目前可售卖并转成局外金币；下一轮处理来源限制后再判定整个供给方案是否可用于正式试玩。真人首炉时间和击杀速度仍未知。

## 第5/10轮：隔离赠料与商人售卖

**发现：** 首次入门赠料和第8杀补料均进入普通库存。玩家可在商人出现后卖出最多三份、失败结算仍存入局外金币，再重开重复；这是每局有限套利，商人并非开局就出现。

**解决及方法：** 两种赠料改记为本局每色 `BrewOnlyStock`，它们可用于炼制，商人单卖与全卖只能取额外可售份数。自然碎片合成、商人买入等额外同色料仍可卖；起炼优先消耗赠料，拒绝结果不退，重开与结束清标记。商人纯赠料时按钮仍会显示可点、点击有不可售提示，下一轮与 Q 页成本反馈一并修正。

**验证：** Editor 编译通过；[60 FPS](../../02_Prototype/AlchemyHD2D/Evidence/BrewV02/60fps-20261103-194214-342-fee9ff5f/native.log)和[10 FPS](../../02_Prototype/AlchemyHD2D/Evidence/BrewV02/10fps-20261103-194334-480-befca32f/native.log)均 `BREW_V02_PASS`，另通过制作人规则和 Boss 规则专项。原生回归覆盖赠料不能出售、额外自然/购买料可卖、全卖保留赠料、起炼优先消耗、拒绝与重开。未验证真人是否觉得材料来源清楚，也未判定第8杀阈值已平衡。

## 第6/10轮：同色成本与可售反馈

**发现：** Q 页把同色主辅材分别显示为同一库存，起炼却合并扣料；商人页只剩炼制专用赠料时，卖出按钮仍显得可用。玩家难以预判同色合计消耗、余额和拒绝结果后的材料损失。

**解决及方法：** 提取 `BuildBrewCost` 给起炼校验、实际扣料与 Q 页共用。Q 页按颜色显示本炉需要、现有、剩余或缺口，同色合计，异色分别列出；明确起炼即扣、拒绝成品不返料，虚空晶另列成本。商人卡片显示可售份数，纯专用赠料禁用卖出操作。

**验证：** Editor 编译、[60 FPS](../../02_Prototype/AlchemyHD2D/Evidence/BrewV02/60fps-20261103-203050-346-6803d405/native.log)和[10 FPS](../../02_Prototype/AlchemyHD2D/Evidence/BrewV02/10fps-20261103-203137-716-09c41b49/native.log)炼药专项通过。原生回归覆盖同色充足/不足、异色分别扣、缺晶不扣及拒绝不返。隔离截图核对了[同色充足](../../02_Prototype/AlchemyHD2D/Evidence/PC_UI/BrewV02_PC_1280x720_2234649274.png)、[同色不足](../../02_Prototype/AlchemyHD2D/Evidence/PC_UI/BrewV02_PC_1280x720_2395990931.png)、[1024×768异色](../../02_Prototype/AlchemyHD2D/Evidence/PC_UI/BrewV02_PC_1024x768_2565836644.png)与[2560×1080同色](../../02_Prototype/AlchemyHD2D/Evidence/PC_UI/BrewV02_PC_2560x1080_2758581724.png)，文字和按钮未交叠。视觉证据保存在本地忽略目录，未随 Git 上传；真人理解度未验证。
