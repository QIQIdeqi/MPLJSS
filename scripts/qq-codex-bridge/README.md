## 启动

1. 在 QQ 开放平台已有页面展开“查看手动连接参数”，复制 AppSecret。不要点击重置。
2. 保存其他工作，**完全退出 ChatGPT/Codex 桌面端**（包括托盘）。这是把桌面端从独占服务切换到共享服务的必要步骤。
3. 在 PowerShell 中运行：

```powershell
& 'D:\06_独立游戏\00_冒牌炼金术士\scripts\qq-codex-bridge\Start-Bridge.cmd'
```

4. 在隐藏输入提示中粘贴 AppSecret 并回车。密钥只传入本次服务的运行环境，不保存到磁盘或日志。脚本会验证 QQ 网关连接，再自动重新打开桌面端。
5. 打开**原来的 QQ 连接聊天**。不要新建聊天。
6. 首次启动时，PowerShell 会显示 `/bind ...`。把完整配对命令**私聊**发给“冒牌炼金术士”。此命令只用于绑定，不能转发或公开。
7. QQ 发送 `/status`。应显示上述聊天 ID、桌面连接数至少为 1，聊天状态为 `idle` 或 `active`。若为 `notLoaded`，请先在桌面打开原聊天。
8. QQ 发送“只回复：QQ连接成功”。**该消息须在桌面原聊天中出现，且 QQ 收到对应回复，才算双向验证成功。** 在此之前不要宣称连接完成。

启动入口 `Start-Bridge.cmd` 为新启动的 Windows PowerShell 进程指定 `RemoteSigned`，允许运行本地脚本，不修改用户或系统的永久执行策略，也不覆盖组织组策略。也可直接双击此 CMD 文件。若仍被组织策略阻止，请保留错误文本供排查。

## 使用边界

### 图片回传与炼金小屋测试

桥接回复支持最终回答中的本地Markdown图片（`![说明](<绝对路径>)`），通过腾讯SDK上传并发送真正的图片消息；文字路径不代表发图成功。仅允许共享内容目录、该成员自己的工作目录与该会话自己的生成图片目录；验证真实路径避免跨成员/受保护目录读取，并检查PNG/JPEG/GIF/WebP文件头。本桥接每次最多发送4张、每张最多20MiB，不下载任意外部URL。

重启加载新版桥接后，在绑定群真实 @ 机器人发送 `/image-test`，会回传 `00_Doc/测试素材/2026-10-27/alchemy-cottage-test.png`。普通任务最终回答中的合规图片也会自动发回相同请求目标；超时后 `/result` 可按所在页取回图片。其他成员会话映射、文字/result及仅@模式保留。

本App独立主动发图实际返回40034105，故已停用该测试路径。`Send-TestImage.cmd`现在仅检查绑定群、图片及运行版本，并提示在群内真实 @ 发送 `/image-test`；不再索取AppSecret或尝试主动发图。新版ready.json包含imageReplyVersion=local-images-v1，用于区分磁盘代码已更新与当前进程真正已加载。

只有腾讯返回发送消息ID后才写 `qq_test_image_delivered` 或 `qq_images_delivered`；仅有上传成功不能当作发送成功。源码测试及本地测试图预检已通过，实际QQ送达仍需凭据输入与发送回执核验。

### 群讨论背景：只接收，不主动回复

**当前关闭：用户于2026-10-27选择继续仅 @ 模式。`useGroupContext=false`，不记录普通群消息，也不把群背景注入任务。以下为保留的待启用实现说明；腾讯侧权限未确认，未通过群内全量消息验收。成员独立会话和/result继续保留。**

按2026-10-27授权，桥接可保存指定群的普通文字讨论，只有真实 @ 本机器人才回复。私聊和其他成员独立会话历史不汇入群背景；普通群消息不启动模型、不占项目锁、不执行文件修改。@时引用最近30条公开讨论作为明确标记的非指令资料，任务仍进入发送者自己的聊天。

背景记录在Git忽略且受保护的 `.runtime/group-context.json`；最多200条，每条最多1000字符，读取和新增时剔除24小时前的记录；离线时不承诺定时物理删除。只处理启动后实际收到的事件，不主动拉取旧历史、不下载或识别附件。换绑/解绑群会清空背景。

腾讯侧必须实际向本App推送 `GROUP_MESSAGE_CREATE`；SDK已支持该事件，当前GROUP_AND_C2C订阅保持不变，不靠猜测增加intent位。请在QQ开放平台/群机器人管理核对全量群消息相关权限，选项是否存在以该App和群的实际界面为准。重启后先发不带@的测试文字，再 @ `/status`；只有显示“已收到未@的普通群消息”才算接收链路验证通过，随后 @ “总结刚才讨论”核对背景是否正确。未获平台推送时本地代码无法读取普通消息。

### 长任务结果查询

- 在已绑定群内真实 @ 机器人发送 `/result`（或“查询结果”），获取**自己最近一次任务**的最终回答。长回答用 `/result 2`、`/result 3` 翻页；不接受成员ID或聊天ID参数。
- 超过4分钟回复窗口时，任务继续运行并保持项目占用；完成后保存最终回答。过期目标不强行主动补发，成员用新消息建立有效回复窗口查询。任务仍在运行时会提示等待，查询不会重新执行任务。
- 结果按既有成员路由键隔离，保存在受保护且Git忽略的 `.runtime/results.json`；服务重启后保留。查询不获取项目锁、不启动模型、不切换会话、不改变其他成员映射。群内查询回答仍对群成员可见，独立上下文不等于群消息私密。
- 缓存缺失时，从该成员自己的历史读取；已记录任务则严格匹配该任务ID，漏收结束通知时也可恢复。查询失败或无法确认完成时不会清除项目锁或宣称任务成功。保存的是Codex最终回答；如果回答明确说后台工作未完成，不能把 `completed` 当成后台工作已成功。
- 本功能需要重启桥接加载。四个测试文件覆盖权限路由、项目锁、结果持久化/隔离/分页和群背景；真实后台已验证旧超时任务结果读取及成员映射不变，QQ实际命令收发需重启后验收。

- 保留主人私聊；已绑定群的成员均可 @。当前不保存普通群消息；模型任务只接受真实 @（事件、结构化标记或本机器人ID标记），忽略其他群和机器人发送者。首次提问为新成员创建独立聊天，同一成员后续复用原聊天；主人继续使用原聊天。配对和群绑定命令不进入模型任务。
- 桌面尚未连接或原聊天尚未被桌面加载时拒绝运行任务，防止把另一个运行实例误当原聊天。
- 各人聊天上下文分开，项目文件共享。为避免从自然语言猜测改动范围，桥接保守地串行派发所有项目请求（包括普通问答）；`/status` 不占用项目锁。占用时回复“项目文件正在被使用，请稍等”，请求未执行、不排队、不插队，任务结束后由用户重发。
- 项目锁在派发前取得，收到对应聊天和对应轮次的完成事件后才释放。QQ 回复超时不释放锁；启动结果不确定时也保留锁。停止/重启脚本发现占用时拒绝停止。桥接还会检查已知聊天的桌面任务状态；这不是操作系统级文件锁，不拦截外部编辑器或桌面后来手动发起的新任务。多人使用期间应避免另行手动编辑同一批文件。
- 回传本次 QQ 任务的最终文字到请求来源：私聊请求在私聊回复，群内请求在该群回复。群内回答可被该群其他成员看到。最多 3800 个 Unicode 码点；过长回答的完整内容在桌面查看。图片、附件、工具日志和桌面发起的其他任务不自动转发给 QQ。
- QQ 被动回复窗口和长任务有限制。超过四分钟不再等待 QQ 自动回复，原任务可能仍在执行，请在桌面确认，勿重复发有副作用的命令。
- 交互式审批和输入不自动批准。QQ 发起的任务如果需要这类交互，需在桌面完成任务。
- 普通成员可修改共享的 `00_Doc`、`02_Prototype`、`03_Build`，拥有各自的 `.qq-workspaces/<成员哈希>/` 临时目录与操作记录。其命名权限配置关闭命令网络访问，拒绝读取桥接运行目录和其他成员临时目录；不开放桥接维护脚本或账号操作。主人的原会话权限不变。

## 更新已有群：全员 @、独立对话、项目占用等待

1. 本次代码更新需要加载：复制现有 AppSecret，完全退出桌面端后，在 PowerShell 运行以下命令。`-Restart` 仅在桌面端已经退出时停止旧桥接，随后启动新版；原聊天 ID、私聊配对和历史保持不变。

```powershell
& 'D:\06_独立游戏\00_冒牌炼金术士\scripts\qq-codex-bridge\Start-Bridge.cmd' -Restart
```

2. 按提示输入 AppSecret，待桌面重开后打开原来的这条聊天。**已经绑定的群无需重新绑定**，新版启动时为该群开启全员模式。
3. 每位成员直接在指定群 @ 机器人提问即可；无需私聊配对。群回复带成员会话标签，发送 `/status` 可查看自己的聊天 ID。不同成员的 ID 应不同，同一成员反复查询保持一致。
4. 让 A 发起一个项目任务，在 A 完成前让 B @ 提交另一请求：B 应收到文件占用提示，且不得新增任务。A 完成后 B 重发，才开始 B 的任务。

新绑定或更换目标群时使用以下流程：

1. 按原启动流程启动并完成主人私聊配对。
3. 在已配对的 QQ **私聊**中发送 `/group-bind`。机器人会私聊返回有效十分钟的一次性 `/bind-group ...` 命令。
4. 由你本人在目标群中，使用 QQ 的 @ 功能选中“冒牌炼金术士”，再发送完整 `/bind-group ...` 命令。机器人需要已在该群；平台若不允许机器人入群或不投递群事件，需先在 QQ 平台完成对应配置。
5. 收到“本群已绑定”后，主人 @ 发送 `/status`，应仍为原聊天 ID；其他成员首次提问创建新聊天，随后 `/status` 显示各自的 ID。
6. 验收至少两位不同成员的往返消息、上下文连续性和占用等待；其他群、非 @ 消息仍不得转发。

只保留一个指定群；重新领取绑定码并在另一个群完成绑定会替换旧群。QQ 私聊 `user_openid` 与群 `member_openid` 分开保存，不假设两者相同。一次性绑定码将私聊控制权与本次发码的群内身份关联，绑定成功即销毁票据。只允许私聊主人领取或撤销群绑定；不要把未使用的绑定码交给他人。

在已配对私聊发送 `/group-unbind` 可立即关闭群接入并作废尚未使用的绑定码，保留私聊功能。群身份与群标识只存放在受保护且 Git 忽略的 `.runtime/group.json`，事件日志不记录绑定码、群标识或消息正文。

## 存储与恢复

所有新增文件在当前 SSD 工作区。依赖在此文件夹 `node_modules`；缓存、服务状态、配对码、主人标识、控制接口令牌及不含消息正文的事件日志在 `.runtime`，均已忽略 Git。启动器将 `.runtime` 权限收紧为当前 Windows 用户。

成员映射在 `.runtime/member-threads.json`，项目占用状态在 `.runtime/project-lock.json`；个人工作目录 `.qq-workspaces/` 已忽略 Git。映射按群标识＋成员标识的 SHA-256 建立，不根据昵称判断身份。不要删除映射文件，否则新提问会创建新的空白会话。

当前 Windows 版本的旧 `workspaceWrite.readOnlyAccess` 参数已失效，使用命名 `permissions` 配置。MXC 文件工具自动读取 AGENTS 时缺少 SYSTEMROOT，因此成员会话禁用该自动加载/宿主技能发现，改由桥接显式加载全局与项目 AGENTS、默认 stop-that-shit/ponytail 规则；文件操作仍受命名权限限制，可用受限 shell 处理文件。启动器会先用独立临时 App Server 验证允许写入、保护目录读写拒绝和受限聊天创建；失败不会停止旧桥接，不会降级无限制权限。该测试不运行模型，也不创建实际群成员聊天。

两个接口只监听 `127.0.0.1`，每次启动自动分配空闲端口，都要求鉴权；实际 `backendPort`、`desktopPort` 写入 `.runtime/ready.json`，启动器自动传递桌面连接地址，不需要手填端口，不配置公网监听或永久环境变量。

2026-10-27 修复重启失败：曾观察到旧 PID 已不存在但 Windows 仍保留旧固定端口的监听。新版不再依赖 43175/43176 空闲；停止脚本校验进程后等待其退出，启动器使用新端口避免残留监听阻塞。截图中的“桌面尚未退出”是独立的启动保护，仍需先完全退出桌面端再执行重启命令。
