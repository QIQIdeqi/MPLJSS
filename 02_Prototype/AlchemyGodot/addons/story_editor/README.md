# 剧情编辑器 · 第一版

这是独立的剧情配置工具；它不会把配置自动接进战斗、选关、村庄、正式剧情或游戏存档，也不会执行条件和到达事件。

## 打开

使用 Godot 4.7.2 Standard 导入本工程的 `project.godot`，在顶部主屏页签选择 **剧情**；如果没有页签，在“项目 → 项目设置 → 插件”启用“剧情编辑器”。

也可以在 FileSystem 打开 `res://addons/story_editor/editor.tscn` 后按 **F6**，独立运行同一个工具；不要按 F5，F5 仍是原游戏入口。

## 操作闭环

1. 点击“+ 剧情节点”，填写节点名称；工具生成 `story_<随机十六进制>` 稳定 ID，改名和保存不会改变它。
2. 可勾选唯一一个可选条件 `completed_level`，输入稳定关卡 ID；未勾选时没有此条件，勾选后留空会阻止保存。
3. 战前绘本和战后绘本是独立空槽，可分别选择项目内、通过校验的绘本 `.tres`；选择其他资源类型会被拒绝。
4. 点击槽位“编辑 / 新建”进入同一套绘本工作台：已绑定时打开现有绘本，空槽时建立未保存绘本。
5. 保存绘本后，`document_saved(path)` 信号会自动把保存路径绑定到进入时的那个节点与槽位；再保存剧情配置，才将引用持久化。
6. 点击“← 返回剧情”保留原选中节点；若绘本仍有未保存修改，会先询问，取消继续编辑，确认仅丢弃内存修改，不删绘本文件或原引用。
7. 用工具顶部“保存 / 另存为”将剧情写成项目内 `.tres`，随后可打开再编辑。
8. 删除节点必须通过确认对话框；取消不删，确认只删配置节点，不删除任何被引用绘本。

在剧情主屏离开到其他 Godot 页签时，配置仍留在内存；关闭主编辑器会通过插件的未保存状态提示，独立 F6 窗口关闭也有未保存确认。新建或打开其他剧情配置时，同样先处理未保存修改。

## 条件和保存边界

`completed_level_id` 是稳定 ID 字符串，不是显示名称或列表序号；当前只检查启用时非空，**没有连接真实关卡目录，也没有验证该关卡确实存在或已经完成**。

剧情保存与绘本保存是两个资源文件：修改已绑定绘本并保存，会更新那个绘本文件，引用仍保持原路径；“另存为”绘本时，会把当前槽位改绑到新路径；返回时放弃尚未保存内容不会撤销已经落盘的绘本保存。

如果将同一个绘本绑定到多个槽位，它们共享文件，之后保存该绘本会影响所有引用方；需要独立内容时请先另存为。

只有 `res://` 项目内资源路径可作为绘本引用，不读取 `00_Doc` 原图绝对路径；当前编辑器不批量搬运外部文件、不自动创建关卡或运行剧情。

## 数据结构

运行时可携带的纯数据资源放在 `res://scripts/story_editor/`，不位于导出排除的 `addons/` 中，但本版本并没有安装触发器。

`story_document.gd`：

| 字段 | 类型 | 作用 |
| --- | --- | --- |
| `title` | String | 配置资源标题 |
| `nodes` | Array[Resource] | `story_node.gd` 节点列表；列表顺序不改变 ID |

`story_node.gd`：

| 字段 | 类型 | 作用 |
| --- | --- | --- |
| `node_id` | String | `story_` 前缀稳定 ID；文档校验拒绝重复 ID |
| `title` | String | 可编辑节点名称，不得为空 |
| `condition_enabled` | bool | 是否配置 `completed_level` 条件 |
| `completed_level_id` | String | 启用条件时必填的稳定关卡 ID |
| `before_book_path` | String | 战前绘本 `res://...tres`，空串为未绑定 |
| `after_book_path` | String | 战后绘本 `res://...tres`，空串为未绑定 |
| `arrival_events` | Array[Dictionary] | 保留的扩展数据，不执行 |

`story_document.validate()` 检查节点类型、ID 格式和唯一性、名称、条件参数以及绘本引用的类型和内容校验；空文档允许保存。

## 到达事件扩展接口

工作台提供：

```gdscript
register_arrival_event_editor(event_type: String, factory: Callable) -> void
```

每项事件约定包含 `type` 字符串，其他键由对应扩展定义，例如：

```gdscript
{"type": "show_notice", "message": "仅作数据示例，不会实际执行"}
```

工厂签名为 `factory(event: Dictionary, on_changed: Callable) -> Control`；工厂收到事件的深拷贝，并返回用于编辑它的控件，提交时调用 `on_changed.call(updated_event)`，工作台按稳定节点 ID 和事件下标写回并标记未保存。

未注册类型会以“数据保留，未注册编辑器 / 未执行”显示；没有事件时显示扩展占位。第一版没有通用事件创建器、事件执行器、游戏触发或存档写入；事件可以由专用扩展或资源 Inspector 配置。

## 验证入口与局限

自动集成测试入口：

```sh
godot --headless --path <AlchemyGodot目录> --script res://tests/story_editor_smoke.gd
```

测试通过实际 `editor.tscn`、按钮和对话框信号检查节点 ID、条件、双槽引用、内嵌编辑、返回取消/放弃、保存自动绑定、保存重开、删除确认和引用文件不变；临时文件若已存在会拒绝覆盖，测试结束清理自身创建的资源。

Headless 或信号驱动测试不等于原生鼠标界面验收；原生界面和 Windows 导出应分别验证。
