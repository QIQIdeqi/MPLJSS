# 头部字体原生对比：现用 DejaVu 与 STIX

2026-11-01，北京时间；基线0f0aa1d。前轮四字段纵向校准属于progress。本轮制作人整合，UI/关卡岗位比较字形与字面，工程QA检查运行态隔离；不把候选载入成功当成字体还原通过。

## 制作人判断

**本次同字号、同布局的五字段比较，STIX没有整体优势，保留现用DejaVu。** 候选等级宽度接近参考，但整体字面更小/更轻；击杀、计时和金币明显收窄，且多字段字面下沉约5像素。没有调整正式字体或为未采用的候选反向移动已校准的生产坐标。

| 字段 | 参考高亮框宽×高 | 当前 DejaVu | STIX 候选 | 观察 |
| --- | --- | --- | --- | --- |
| Lv 12 | 56×18 | 65×18 | 55×16 | 宽度更近，但更矮，候选顶部35而参考30 |
| 320 / 320 | 84×13 | 93×16 | 75×13 | 字高接近但过窄，位置也不同；原HP框残字仍另行待决 |
| 05 : 28 | 87×20 | 91×20 | 74×19 | 当前更近；候选顶部27，参考22 |
| 532 | 41×18 | 41×18 | 34×16 | 已接近的字段发生退化；候选顶部25，参考20 |
| 1,240 | 63×22 | 63×20 | 51×17 | 候选更窄、更矮；金币使用独立金色阈值 |

这只是当前字号/五串文本的判断，不证明原图使用何种字体，也不证明STIX在重新校准字号后必然不适用。等级前缀Lv与数字的相对层级仍是独立视觉差异，不能靠整体包围盒接近认定已修复，亦未据此预定精确字号或控件结构。

## 可复现方式与隔离范围

先编译当前Editor目标，在项目目录运行：

```powershell
./Tools/TestReference60.ps1
./Tools/TestReference60.ps1 -STIX
```

默认路径使用保存的当前字体；`-STIX`同时传`-Reference60Test -ReferenceSTIX`，仅在已确认bCapture的夹具Step0替换五个运行态TextBlock的FontInfo。克隆原FontInfo后只清FontObject、设置临时FCompositeFont；字号、间距、outline、坐标、颜色、阴影和测试数值保留。候选字体从[项目ArtSource候选目录](../../../ArtSource/TypographyCandidates_20261101/README.md)读取，原始TTF/完整许可证/来源哈希随附；不导入正式Font/FontFace资产，不保存或重建Widget。

两种模式输出到不同Evidence目录，默认输出与现有调用方式保留。原生默认34项/28个名称、候选40项/34个名称通过，共74项，无FAIL；额外6项只确认字体文件和五个节点可用，不属于美术验收。最终Editor/Game编译通过。候选后又复验了默认路径，当前图来自同一Editor二进制；WBP_BattleReference字节SHA仍与0f0aa1d校准后完全相同。

没有修改默认字体、生产Widget、存档、镜头、数值；没有Cook、打包或发布。Game编译不等于ArtSource中的候选字体已进入发布包。HP框10个原字像素、小地图底纹亮斑、正式字体/字宽/前缀层级仍按工作台维护，未因本次研究而标完成。
