# HP 与小地图素材逐像素清理

2026-11-01（北京时间）。基线 bfaee77；用户明确选择“用脚本逐像素清理现有素材”。制作人整合，工程 QA 只读复核，UE 作业由制作人串行执行。

## 实际改动

- HPFrame 保持 306×32。只将 Y7、X16–280（含端点）的 265 个条内像素 alpha 置零，其中包括已定位的 10 个原数字残顶；RGB 和其余所有像素保持原样。右端 X281–286 的暗边及金色斜边没有扩大清除；原框的内沿装饰保留。
- 原透明孔实际宽 271。现有 HPBar 从位置 (213,35)、尺寸 270×16 调整为 (213,34)、271×17，使新增行及原孔完整由真实血量填充；同步原生默认和已有 Designer 槽。没有重建 Widget 树。
- MinimapDark 保持 21×15，仅修补 X1–4、Y2–5 的 16 个像素，以同排未改动的 X0/X5 为端点插值。局部最大通道值 152→70，alpha 和区域外像素不变；实时地图格子、玩家及敌人标记仍由原生产逻辑绘制。

[逐像素变更](pixel-changes.json)、[独立保留/取色核验](pixel-verification.json)和[定点导入记录](import.json)可核对实际范围。两张纹理均定点重导，未调用会重建 Designer 树的全量 ImportReferenceUI。

## 复现与验证

`Tools/CleanReferenceUI.py --apply` 清理现有 PNG，省略参数只检查；再次检查为 0 个待改像素。`ExtractReferenceUI.py` 复用同一清理函数，manifest 记录额外孔和局部修补范围，重新提取不会恢复残字或亮斑。

Editor/Game 最终编译通过。`Tools/TestReference60.ps1 -HPCleanup` 加入隔离的满血/半血/空血样本，分别在 1672×940、1024×768、2560×1080 运行，57+57+61=175 项通过、无 FAIL，各保存 14 张原生图。增加的样本等待 UMG 渲染，检查真实百分比/数字绑定和控件几何；采样后恢复 HP，再继续原有真实受击、死亡与结算检查。日志及源图/资产 SHA 见 [verification.json](verification.json)。

`Tools/VerifyReferenceUICleanup.py` 对保留的原始 ReferenceHUD 重建旧遮罩，逐像素核对清理区外无变化及 10 个残顶已透明；并检查参考分辨率实际原生图 Y34 的 X240/X365 两点：满血均红、半血左红右暗、空血均暗。该取色只证明这些点，不能当作整条逐像素验收。

制作人已查看 [三种血量](hp-samples.png)、[4:3 与超宽空血](responsive-empty.png)及[小地图](minimap.png)，[完整原生图](hud.png)保留原尺寸。裁剪图只做展示性裁切/最近邻放大；HP0 图为冻结渲染样本，不宣称它是自然死亡画面。

[静态图元比较](static-artwork.json)中，另外 10 项、34,716 个不透明像素仍 RGB 完全一致。HP 框有 104 个像素受运行文字/阴影覆盖，不能把这一数目说成素材残字或宣称整 HUD 已 1:1；最终字体与复杂同屏/自然有声试玩仍未验收。本次没有更换字体、数值或生成规则，没有 Cook/打包/新发布。
