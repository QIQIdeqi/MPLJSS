# 等级前缀层级与长数值适配

2026-11-01，北京时间；基线ff7bc07。前轮字体观察为progress，STIX整套同字号替换未采用。本轮制作人整合，工程QA协助核对引擎反射/字体量化，沿用现有DejaVu字体，处理等级的视觉层级和数值宽度。

## 当前修改

原`LevelText`的整串`Lv 12`共用18字号；现在保留原数字控件对象、名字和GUID，将数字迁入`LevelNumberFit`，增加常量`LevelPrefixText`。前缀使用14字号，数字保持18与字距-83；这两项是本轮实现参数，不是对原图精确字号/字距的认定。数字容器位于(160,26)，37×33，只缩小不放大、横向靠左，短值顶部对齐、长值垂直居中，并裁切到边界；新前缀位于(129,30)，30×27。原生默认树与已存Designer同步，其他字体/字段保持现有版本。

NativeTick在新树显示纯等级数字；没有新前缀的旧树仍显示`Lv 数字`。这是代码兼容路径，本轮没有重跑旧发布包。长数值由原生ScaleBox处理，保留外层等比适配；不承诺任意长整数都有最低可读字号。

短值不设置额外最小宽度。实际遇到长数值的预检与缩小后字形测量不线性，因此对长数字使用无负字距的字体测量宽度、原阴影及2个物理像素余量作为MinDesiredWidth，并按容器继承的实际布局缩放换算。负字距/像素量化不再使预检宽度小于实际缩小后的需求。相同等级字符串也不再重复SetText；该优化不是修复的唯一原因。

## 迁移与真实失败记录

[迁移脚本](../../../Tools/ApplyReferenceLevelHierarchy.py)仅追加两个控件并迁移原LevelText，没有调用重建树方法。先验证原父级、位置和字号；已有新结构时验证并复用。字体结构通过`get_editor_property('font').copy()`复制，避免前缀调整污染数字。

Python没有暴露TextBlock.get_font，首次调用失败且未保存。第二次结构编译虽然返回true，却触发新控件GUID缺失Ensure，未接受为通过；已从SHA验证的原资产重做。GUID表不开放给Python，因此增加只登记缺失名的原生编辑器入口RegisterDesignerWidgetNames，调用引擎OnVariableAdded并保留旧GUID；重建工具也同步登记新名字，但本轮未执行其覆盖树操作。最终干净迁移无Ensure，重复迁移与旧坐标校准工具运行后资产SHA均不再变化。

首轮等级1000确实被裁断，未通过放宽边界或删除样本绕过。原生诊断：容器37，ScaleBox按预检约58计算比例，缩小后文本报告63.703，实际几何宽40.638。稳定最小测量宽度后，在参考尺寸100/1000的实际几何宽均为37；完整末位另以原生图观察。失败日志/原始截图及原uasset留SSD Evidence/LevelTypography_20261101，不以废弃轮PASS混入结果。

UI终检还发现压力长值虽完整但数字上浮，随后仅对长值增加垂直居中，保留等级12的顶部对齐和参考位置。缩小后的长值仍不保证普通值的字体大小、完全一致的基线或舒适可读性，不能只以几何容纳判定整套排版完成。
