# 默认怪物表：创建失败恢复

2026-11-01，北京时间；基线`b0f8825`。生产按钮仍固定创建缺失的`/Game/Design/DT_Enemies`，读取项目默认CSV。为安全验证，将原创建主体提取为编辑器原生函数，生产包装与隔离夹具调用同一实现；没有新增界面选项或任意运行表选择器。

## 修复

- CSV先导入临时表并校验，成功才创建正式路径对象，坏数据不会占住目标。
- 使用`SAVE_NoError`让本次可恢复的FailedMove保存错误返回false，由工具显示Status；不把保存失败变成成功。
- 保存失败只清理本次新建表：移除公开/独立标记、移动到唯一Transient路径，恢复包原脏状态；保存成功后才通知AssetCreated。
- 已有已保存作者表只加载与校验，不按种子覆盖、不重存，保留尚未保存的修改。已有未保存内存表、异类对象或无法加载的已有文件明确报错，不擅自替换。
- 生产Actor仅在表引用变化时标脏。

## 隔离原生验证

`EnemyCreationTest`将GUID包挂载到项目SSD的`Evidence/EnemyCreation_20261101/packages_<GUID>/`，不在Content或生产DT上试验。三条独立路径在同进程运行，即使前一路失败也继续作者保护检查：

1. 把自己CSV中的HP设0，确认校验失败后没有正式对象、可查资产或文件；改回合法CSV，在相同包路径重试并检查实际文件。
2. 用GUID目录内的普通文件占住目标父目录，触发真实SavePackage失败；检查对象/可查资产/文件不残留，只删除该自建阻挡文件，再同路径重试保存。
3. 独立成功保存一张表，将内存HP改77并设置包dirty，再用坏CSV调用创建；检查同一对象、77、dirty及磁盘SHA1都保持。
