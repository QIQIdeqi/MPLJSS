# 新增普通怪物变体：配置示例

本例演示复用已有行为、奖励和素材的接入方法，不新增正式物种或提出新平衡数值。角色、怪物设定仍在wolai维护；工程显示名不能替代正式人设。完整字段与历史验证见[怪物配置说明](局内战斗表现与怪物配置.md)。

## 1. 打开并确定新ID

确认当前Editor模块与仓库版本一致；刚拉取C++修改时先编译、重新打开Editor。只调整已有DT字段通常不需要重新编译C++。

双击[打开怪物配置.cmd](../打开怪物配置.cmd)，打开生产表`/Game/Design/DT_Enemies`和工具`/Game/Design/BP_EnemyDesigner`。在自己的工作分支操作，先确认同一二进制表没有并行编辑。本文不会自动运行设置脚本或修改任何表。

需要工具按钮时，选中已有BP_EnemyDesigner工具Actor，在Details操作；没有实例时可放入临时编辑关卡再选中，不为这次演示修改正式地图。打开Blueprint资产本身与选中关卡工具Actor是两步操作。

数当前连续行`0..N−1`，新增行取`N`。只有当前恰好11行时，新ID才是11；已经有变体时继续追加，不跳号、不重排、删除或复用发布过的ID。复制0号行到新行，不要把0号原行重命名。原0–10行的Archetype保持同号。

## 2. 配置一张普通变体

| 字段 | 本例操作 | 作用 |
| --- | --- | --- |
| 行名 / Definition | 下一连续数字N | 新实例配置、图鉴发现身份 |
| Name | `普通变体_配置演示` | 工程演示名，不是正式怪物命名 |
| CodexDescription | `复用追逐接触行为的配置演示。` | 可编辑图鉴说明；空值按Behavior生成中性说明 |
| Archetype | 保留复制行的0 | 沿用模板0的奖励/特殊流程；N≥11不会自动变精英 |
| Behavior | 保留Contact | 追逐接触；不新增行为节点 |
| HP、Speed、ContactDamage、成长字段 | 保留当前复制值 | 不在本例提出新起测数值 |
| TunedHP与三种Tuned伤害 | 先核对并保留当前复制值 | 默认B模式优先用非负覆盖；只改主字段可能看不到效果 |
| SpriteKey / MaterialOverride | 先保留复制值 | 先确认数据接入，再替换美术，避免同时改变所有因素 |
| VisualSize / CollisionRadius | 先保留复制值 | 外观尺寸和净空半径分开，不自动缩放攻击距离 |
| EliteWeight | 保持0 | 普通变体不进入精英轮换 |

若后续希望新行只跟随主生命/伤害字段，可把对应Tuned项设为−1；0是实际零覆盖，不是“未设置”。生命必须为正，生成后取整至少1；零伤害仍执行原攻击过程，但不扣血或触发受击/受伤无敌。

当前接触攻击距离按普通模板75cm、精英110cm处理，不能用放大VisualSize或CollisionRadius来推断攻击距离也会变大。范围和远程行为另看Area/Ranged字段；远程满足Min≤Keep≤Max且Max>Min，射击包含端点。

素材替换时，SpriteKey对应`/Game/Art/M_<Key>`及受光版本；也可以指定MaterialOverride。格式校验通过不代表材质存在、透明度/脚点或实机显示正确，换图后需要实际观察。不要把整张预览背景当作怪物透明图卡。

## 3. 决定是否参加自然波次

SpawnWeights必须恰好六档，依次对应第0、1、2、3、4、5分钟及以后，是同档普通怪之间的相对权重，不是百分比。Archetype0–6按它参加普通波次；精英和Boss不能填普通正权重。

- 只做资产/字段准备：新行六档全0，不改变自然波次；此时Play里不会因为新增行就自动刷出它。
- 在实验分支观察普通变体：可以保留从模板复制的六档权重，等待对应阶段的后续波次。这会改变该阶段的相对分布，合入前仍须战斗/数值确认，不能把演示值当正式批准。

不要仅看开局已有敌人就判定新行未生效。非零权重也不保证每波选中；实际生成还受合法出生点、屏外位置和可达性约束。工具当前没有“立即生成此行”的预览按钮。

精英变体另复制7–9，普通SpawnWeights全0，用EliteWeight参加调度，保留对应宝箱/材料/商人解锁身份。新增Boss行也不会替换流程固定生成的行10。这两条不是本普通变体示例的操作步骤。

## 4. 保存、校验、重新Play

保存DT后，使用BP_EnemyDesigner的“校验怪物配置”，检查Status和Output Log，确认行数变为N+1。校验不会代替保存。工具的EnemyTable可以选择校验目标，但运行时始终读`/Game/Design/DT_Enemies`；把工具指向实验副表不会让游戏自动换表。

停止当前Play，再启动新的Play。局内重新开一局不会重新读取DT。编辑器也可能向新PIE提供未保存的内存修改，所以“看见效果”不能替代“已保存”：交接前保存并确认Git实际改动。

| 观察层次 | 可检查的结果 | 不能替代什么 |
| --- | --- | --- |
| 作者校验 | Status显示通过及N+1行 | 不证明材质存在或自然出生 |
| 新Play读入 | 日志`ALCHEMY_ENEMIES_LOADED rows=N+1` | 不证明该行已经刷出或击杀 |
| 实际行为/发现 | 出生、移动/攻击、击杀后对应Definition的图鉴记录 | 不能把一次演示当平衡或性能验收 |

无效表会记录`ALCHEMY_ENEMY_LOAD_FAIL`并停止本次PIE/进程，不会悄悄用默认CSV继续运行。先回到Status提示的行修正，再保存、校验和重新Play。

本例仅是操作文档，本次没有向生产表添加上述演示行，也没有执行该作者流程。此前自动专项使用内存变体或隔离包，不能当作你刚编辑的新行已经验收。

## 5. 提交与排查

提交前核对本次预期改动：目标DT、新美术资源（如有）、来源/许可与配置说明。不要用默认种子CSV整表覆盖作者DT来“恢复”，也不要把本地Evidence、Saved、编译产物混入资源提交。二进制表冲突先按字段核对合并；无法合并时按项目协作原则使用Git版本。

| 现象 | 先查 |
| --- | --- |
| 主HP/伤害改了却没效果 | Tuned覆盖、是否新Play、是否编辑了固定生产表 |
| 校验通过但看不到新行 | 对应分钟档权重、自然随机选择、合法出生点；全0本来不刷 |
| 贴图缺失或像白块 | 实际材质路径、受光版本或MaterialOverride；校验仅保证键格式 |
| 新行被当作错误奖励类型 | 检查Archetype，不能把它填成新Definition数字N |
| 默认表创建失败后重试 | 修正CSV/保存条件后重试；已有未保存对象须先处理，不能靠反复点创建覆盖 |
| 新Play直接结束 | 查`ALCHEMY_ENEMY_LOAD_FAIL`和工具Status，不是假定旧存档损坏 |
