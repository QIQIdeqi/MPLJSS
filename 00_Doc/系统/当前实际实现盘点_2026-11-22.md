# 当前实际实现盘点

> 盘点日期：2026-11-22（北京时间）
> 范围：`02_Prototype/AlchemyGodot` 的场景、脚本、数据与资源引用。
> 方法：静态代码核查，不引用策划正文作为完成依据；未启动 Godot、未做真人试玩或构建验收。
> 目的：为下一步制作提供“当前实际可玩内容”基线。本文件不代表设计定案。

## 1. 当前可走通的玩家流程

```text
开始菜单
  → 村庄
  → 工房实验制作能力（可选）
  → 雾门选择初始/库存能力
  → 普通战场自动战斗、捡资源、升级三选一
  → 300 秒后传送门
  → Boss 战
  → 素材/金币结算
  → F 返回村庄
```

### 1.1 菜单与存档

- 工程入口为 `scenes/menu.tscn`。新游戏会创建 `user://progress.cfg` 并将村庄金币置为 0；已有该文件时“继续”可用。
- 菜单可进入村庄或退出。开始新游戏当前只明确重置金币，不会显式清空材料、能力、配方发现等其他存档段。

主要实现：`project.godot`、`scripts/menu.gd`。

### 1.2 村庄、工房与入场

- 玩家可在村庄移动；靠近右侧雾门按 `F` 打开入场能力选择。
- `Q` 打开炼金工房。工房从五种永久素材中选择不重复材料：投入少于两种、材料不足、超过阶段上限都会被拒绝；成功组合扣除各一份材料并产出能力；失败组合不扣材料。
- 初始能力永久可选且不消耗；六种制作能力只有库存大于 0 才能选择。进入战斗场景后才扣除一份非初始能力。
- 工房图鉴只公开已经成功发现的配方。

主要实现：`scripts/field.gd`、`scripts/alchemy/workbench_ui.gd`、`scripts/alchemy/alchemy_service.gd`、`scripts/alchemy/entry_select_ui.gd`、`scripts/run/profile_store.gd`。

### 1.3 普通战场

- 进入 `battle.tscn` 后会生成战场、普通敌人、HUD、HD 战斗视图、本局素材账本与新技能系统。
- 操作已接入：WASD 移动、Space 闪避；攻击由技能系统自动寻找量程内最近敌人后施放。
- 开局固定拥有“魔法弹”。拾取经验后，达到“当前等级 × 6”经验会暂停并弹出三选一；最多拥有 6 个技能。
- 敌人死亡生成金币、经验及地面素材；进入 40 像素范围会自动拾取素材到本局账本。未拾取素材不会结算。
- 默认 300 秒后开放 Boss 传送门；靠近按 `F` 并确认，切换到 Boss 场地。切场时会清除普通场地尚未拾取的掉落物。

主要实现：`scripts/field.gd`、`scripts/lilita.gd`、`scripts/alchemy/alchemy_system.gd`、`scripts/skills/skill_manager.gd`、`scripts/upgrade/upgrade_manager.gd`。

### 1.4 Boss 与结算

- 进入 Boss 时保留玩家生命和已经拾取的本局资源；普通敌人与场地掉落会清理。
- Boss 已有冲锋与两段扇形弹攻击。Boss 被击杀或玩家生命归零均会锁定玩家、结算已拾取素材、保存金币并显示结果；按 `F` 返回村庄。
- 已拾取素材通过运行账本一次性合并进永久库存，并以已结算 run ID 防止重复结算。

主要实现：`scripts/boss_arena.gd`、`scripts/field.gd`、`scripts/run/run_manager.gd`、`scripts/run/profile_store.gd`。

### 2.2 数据与持久化

- 永久档案包含：五种材料库存、能力库存、已结算 run ID（最多保留 200 条）、配方发现状态及当前投入阶段。
- 正常的战斗结束会把内存中的 `ConfigFile` 写入 `user://progress.cfg`。
- 配方共有 6 个：爆裂、弹射、穿透、追踪、分裂、回响。当前默认投入阶段为 2 种材料。

主要实现：`data/materials/recipe_data.gd`、`scripts/run/profile_store.gd`、`scripts/run/run_manager.gd`。

## 3. 已存在但不属于当前正常可玩主链的内容

这些文件或功能不是“未制作”，但玩家正常从菜单进入游戏时不会以其原设计方式使用；后续制作前应决定保留、迁移还是移除。

1. **旧局内炼丹/丹药系统**：`scenes/brew.tscn` 与 `scripts/brew.gd` 仍被战斗场景实例化，保留 25 技能丹药数据、拖放、炼制、装备和旧投射逻辑；但战斗中的 `Q` 不再打开它，战斗 HUD 也强制禁用炼金按钮，战斗攻击已由新 `SkillManager` 接管。因此它不是当前正常入口可达玩法。
2. **旧 `AlchemyManager` / `AlchemyInventory` 路径**：战斗与村庄仍会创建部分旧对象，但当前工房、库存、入场消耗实际走 `AlchemyService + ProfileStore`，旧路径没有参与主链。
3. **25 技能表**：`data/brew_skills.gd` 仍存在，旧炼丹测试也会读取它；当前主战斗只读取 `data/skills/skill_data.gd` 的 10 个技能。
4. **未引用的视觉素材**：`art/vfx/generated/arcane_lightning_24f_concept.png` 在当前脚本资源引用中未找到使用点；其余 8 张运行时图集均有脚本 preload。
5. **现有 smoke 测试**：`tests/flow_smoke.gd` 与 `tests/brew_rules_smoke.gd` 主要直接操作旧 `brew` 流程，不能作为新“村庄工房—能力—十技能”主链的实机验证。

## 4. 真实缺口、近似实现与风险

以下各项均是从实际调用与实现得出，不是文档计划。

### 4.1 主流程与结算

- **中后期配方不可达**：档案默认最多投入 2 种材料，`set_tier()` 当前没有调用点。因此需要 3/4 种材料的追踪、分裂、回响配方在正常流程中无法制作。
- **主动退出不结算**：战斗暂停菜单会直接切回菜单，没有先执行 `finish()` 或本局素材结算；因此该路径下已拾取的素材和金币不会按正常结束流程保存。
- **Boss 掉落不可带出**：Boss 死亡会生成掉落，但玩家随即锁定，死亡动画结束后立即结算并清除未拾取的地面素材，无法实际拾取 Boss 素材。
- **工房即时落盘缺口**：`ProfileStore.save_profile()` 只更新内存中的 `ConfigFile`；工房成功/失败后若直接 Esc 回菜单，未找到调用 `field.persist()` 的路径，配方和库存变动可能不写入磁盘。
- **金币无消费口**：金币可获得、结算并在村庄显示，但当前未发现商店或其他消费/用途代码。
- **精英掉落当前不可达**：精英掉落表存在，但敌人创建未设置 `elite=true` 的调用路径。

### 4.2 技能与能力

- **战斗伤害多为即时结算**：投射物、回旋、区域等视觉会播放，但大多数伤害在施放函数同一帧结算，视觉飞行/持续时间不决定命中时刻。
- **能力改造没有按 `deep_skills` 限定**：数据记录了每种能力的深度改造技能，但运行时未调用 `SkillRuntime.is_deep()`；携带能力会向全部本局技能施加同一效果。
- **追踪能力无实际追踪分支**：仅有数据定义；伤害层没有追踪实现。
- **回响是即时补伤**：代码只在命中时补一次低伤害，没有按配置延迟复现。
- **风刃返程仅是视觉**：伤害层用单次直线判定近似，没有返程命中逻辑。
- **毒雾没有持续伤害对象**：只在释放帧造成一次范围伤害，并作为元素区域登记。
- **元素联动可触发范围有限**：当前只有区域类技能登记元素区域，实际是毒雾；火+毒、冰+毒具备可形成的检查条件。需要火区域或冰区域的其他联动没有对应区域产生路径。
- **两类升级实际无效果**：候选池会出现“能力强化”和“元素联动强化”，但前者尝试调用不存在的 `upgrade_ability()`，后者为 `pass`。
- **技能升级伤害高于提示文案**：升级时已将基础伤害乘上等级成长，而 `SkillRuntime.damage()` 会再次按等级成长；实际伤害不是界面所写的单层“+12%”。

### 4.3 表现与 UI

- 战斗 HUD 已显示六格技能槽、技能等级、经验、击杀、金币、Boss 血条、小地图及当前技能列表；当前技能槽主要以颜色和 tooltip 区分，没有每技能独立图标。
- `B` / 背包入口仅查看当前运行时技能，不能换装、排序或手动施放。
- 战斗内炼金按钮被强制禁用，`Q` 仅在村庄打开工房。
- 升级 UI 已有三选一按钮且会暂停战斗；当前没有跳过选择的输入路径。

## 5. 本次核查的边界

- 本次未运行 Godot、未执行自动测试、未构建导出包，因此“已接入”表示静态代码和场景调用链存在，不等同于真人画面、操作手感、性能、存档迁移或平衡已经通过验收。
- 工作区当前存在大量 Godot 自动生成的 `.import` 修改与 `.workbuddy/` 未跟踪内容；本盘点没有修改、清理、暂存或提交这些内容。
- 本文件只记录当前代码事实。后续若决定修复或删改遗留系统，应先以本文件的“当前正常主链”作为回归范围。

## 6. 建议的下一步优先级

1. 先决定旧局内炼丹/25 技能系统的命运：迁移进新主链，或明确退役并清理，避免两套系统继续互相干扰。
2. 修复资源闭环：阶段解锁、Boss 掉落、主动退出结算、工房落盘。
3. 补齐能力与升级的真实效果，再处理联动扩展与技能命中时序。
4. 为新的“工房—能力—十技能”主链补一组独立自动验证与一次真人试玩验收。
