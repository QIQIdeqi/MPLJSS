# 2. 项目系统设计基线

## 2.1 已确认的项目基线

| 项目 | 基线 |
|---|---|
| 核心类型 | Survivors-like 自动战斗、生存、素材掉落、配方探索与技能构筑 |
| 运行方式 | 单人游戏；PC / Steam；Unity |
| 战斗操作 | WASD 移动；Space 闪避 / 短距离冲刺；技能主要自动攻击；部分指向性技能自动释放但方向由鼠标位置决定 |
| 普通怪与精英怪 | 普通怪按时间波次生成；普通怪和精英怪可掉落局内货币；普通怪可掉落普通炼金素材；精英怪必定掉落宝箱 |
| 最终 BOSS | 当前 Demo 为单一固定关卡的最终 BOSS；战斗与时间线以关卡 / 战斗策划案为准 |
| 局外据点 | 独立的俯视角小型区域，玩家可自由移动，通过设施交互打开功能界面 |
| 长期成长 | 仅确认局外永久数值强化；暂不把内容解锁系统加入已确认制作范围 |
| 配方探索 | 玩家通过组合素材发现配方；发现记录永久保存 |
| 单局货币 | 无论本局胜利或失败，正常结算前已经收集的货币均进入局外账户 |
| 局内素材 | 单局结束后清空，不转入局外库存 |
| 玩家进度 | 单存档；关键数据变更时自动保存；主存档与备用存档共同维护 |
| 游戏设置 | 单独保存；重置玩家进度时保留设置 |

## 2.2 系统设计原则

1. **局内与局外资源分离。** 局内素材用于配方探索与技能制作，局内货币在本局结束时结算为局外货币；只有局外货币用于永久强化。
2. **配方数据与玩家发现记录分离。** 配方是否存在是内容数据定义；玩家是否已发现是存档记录。不能因为玩家尚未发现，就让系统认为配方不存在。
3. **核心规则配置驱动。** 配方需求、技能上限、强化等级价格、连锁冷却与目标范围等由配置数据管理，避免在代码中为每条内容写分支。
4. **高风险操作必须可恢复。** 永久强化购买、存档恢复和重置进度都需要明确反馈；保存失败不得覆盖原有有效存档。
5. **局内系统界面不制造额外战斗压力。** 打开局内任何系统界面时暂停整个游戏模拟与所有游戏计时；UI 动画可使用非游戏时间继续播放。
6. **Demo 先闭环，再扩展。** 本次优先实现一个主菜单、一个据点、一个战斗关卡、一个炼金强化设施、一套图鉴入口和可工作的存档系统。

# 3. 系统关系与整体游戏循环

## 3.1 核心游戏循环

**主菜单 → 进入据点 → 通过战斗出口打开关卡选择 → 进入战斗 → 收集货币与素材 / 探索配方 / 组合技能 → 胜利或失败 → 结算货币并清空局内临时状态 → 显示结算界面 → 玩家确认 → 返回据点 → 永久强化 / 查看图鉴 → 再次进入战斗。**

## 3.2 系统关系图（文字说明）

- **主菜单**提供开始游戏、局外成长、配方图鉴、游戏设置、退出游戏五个入口。
- **据点**承载角色自由移动和场景设施交互；主炼金设施打开永久强化界面，独立图鉴设施打开图鉴，独立传送出口打开关卡选择。
- **局内战斗**持有本局素材、临时技能装备、技能背包、连锁运行状态、本局收集货币、击败数和战斗时长。
- **局外玩家进度**保存货币余额、永久强化等级、已发现配方 ID 等长期数据。
- **设置数据**独立于玩家进度保存，包括画面、音量、自定义键位与当前开放语言。

## 3.3 数据归属规则

| 数据 | 生命周期 | 是否写入玩家进度存档 |
|---|---|---|
| 局外货币余额 | 跨局长期保存 | 是 |
| 永久强化等级 | 跨局长期保存 | 是 |
| 已发现配方 ID | 跨局长期保存 | 是 |
| 画面 / 音量 / 键位设置 | 跨局长期保存、独立文件 | 写入设置文件，不写入玩家进度文件 |
| 局内材料数量 | 单局 | 否；本局结束清空 |
| 当前装备技能与技能等级 | 单局 | 否；本局结束清空 |
| 技能背包内容 | 单局 | 否；本局结束清空 |
| 连锁的冷却、运行状态与本局触发次数 | 单局 | 否；本局结束清空 |
| 本局收集但尚未结算的货币 | 单局临时累计 | 正常结束时转入玩家进度；不作为可继续的战斗存档 |
| 本局时长与击败数量 | 单局统计 | 本次结算展示；Demo 不要求保存历史战绩 |

# 4. 游戏启动、主菜单与场景流转

## 4.1 启动流程

1. 启动游戏，初始化本地文件系统、配置数据和输入系统。
2. 先读取独立设置文件；若文件不存在或无法解析，创建默认设置并提示（仅在确有异常时提示）。
3. 检查主存档与备用存档状态，并校验版本、必需字段与数据完整性。
4. 若主存档与备用存档都不存在，视为首次启动，创建初始玩家进度；若主存档缺失但备用存档有效，或任一已有存档损坏，则按第 13 章展示恢复选项。
5. 进度初始化或恢复成功后进入主菜单；主菜单默认不自动开始战斗，也不自动进入据点。

## 4.2 主菜单入口

| 入口 | 行为 | 备注 |
|---|---|---|
| 开始游戏 | 加载局外据点场景；角色在固定出生点生成并恢复操作 | 不直接进入战斗 |
| 局外成长 | 直接打开永久强化界面 | 与据点中主炼金设施打开同一功能界面，不复制一套业务逻辑 |
| 配方图鉴 | 直接打开局外图鉴界面 | 局外只能查看，不能制作技能 |
| 游戏设置 | 打开设置界面 | 修改后的设置独立保存 |
| 退出游戏 | 退出应用 | 建议有一次确认，避免误触；属于常规 UX 补充 |

## 4.3 场景与 UI 转场

- 主菜单与据点是不同的使用状态；主菜单上的局外成长、图鉴与设置是快捷入口，不要求玩家先进入据点。
- 据点中的设施打开对应 UI 时，不需要重新载入主菜单场景。
- 战斗入口进入关卡选择 UI；Demo 当前只有一个可选战斗关卡。
- 战斗加载完成后进入本局初始化与正式战斗；加载期间禁止玩家重复提交进入请求。
- 胜利 / 失败时先完成结算事务，之后显示统一结构的结算 UI；点击确认后加载或返回据点，并在据点出生点恢复角色操作。

# 5. 局外据点与设施交互

## 5.1 据点定位

据点是独立的正俯视 2D 小型可探索区域。玩家可以操控角色移动，但 Demo 暂不增加 NPC 对话、任务、仓库、装饰或其他额外设施玩法。场景内的装饰可用于氛围与引导，但除指定设施外不要求有功能性交互。

## 5.2 Demo 最小设施清单

| 设施 | 交互方式 | 打开功能 | 当前范围 |
|---|---|---|---|
| 主炼金设施 | 靠近后按交互键 | 永久数值强化界面 | 必做 |
| 配方图鉴设施 | 靠近后按交互键 | 配方图鉴界面 | 必做；同时保留主菜单快捷入口 |
| 战斗出口 / 传送设施 | 靠近后按交互键 | 关卡选择界面 | 必做；当前只列出 Demo 关卡 |

## 5.3 交互规范

- 建议默认交互键为 **E**，可在操作设置中修改；具体键位由设置系统控制，不能在设施脚本中写死。
- 进入设施有效交互范围时显示名称与操作提示；离开范围后提示隐藏。
- 同一时刻只允许一个设施成为当前交互对象。若多个设施的有效范围重叠，优先选择与玩家距离最近的可交互设施；距离相同时按稳定的优先级 ID 处理。
- 按交互键时，若已有阻塞式 UI 打开、场景正在切换或角色输入被禁用，不重复触发交互。
- 打开设施界面后，玩家移动输入被屏蔽。局外不需要暂停战斗系统，因为据点不运行战斗模拟。
- 关闭界面后回到据点，角色位置保持打开界面前的位置，不自动传送或重置。

## 5.4 场景设计边界

- 据点是功能型小场景，不要求随机生成。
- 三个必做设施均需明确可识别的视觉轮廓与交互范围；碰撞层与装饰层分离。
- 角色初始位置应避免紧贴设施、地图边缘或不可通行障碍。
- 不要求在据点中复制战斗地图的怪物生成、掉落物或 BOSS 逻辑。

# 6. 战斗入口、关卡选择与单局生命周期

## 6.1 关卡选择界面

- 玩家在据点与战斗出口交互后打开关卡选择界面。
- Demo 当前只提供一个已开放的固定战斗关卡。界面展示关卡名称、简短玩法目标及「进入战斗」操作即可。
- 不需要本次实现多关卡解锁、难度选择、随机地图或战斗模式选择。
- 若将来增加关卡，关卡选择列表应读取配置数据，不在 UI 代码中按关卡数量写死。

## 6.2 战前配置预留

项目方提出未来可能加入开局配置（技能、强化甚至职业），但玩法尚未决定，故不纳入 Demo 功能实现。程序应在启动本局时保留可扩展的 `RunLaunchOptions` / `PreRunConfig` 数据入口；当前 Demo 使用默认空配置，关卡选择确认后直接开始加载战斗，不显示未完成的职业或技能预选 UI。将来增加战前配置时只需在进入战斗前插入可选步骤，不应重写战斗初始化链路。

## 6.3 单局生命周期

1. **准备加载：** 校验关卡 ID、设置本局上下文，清理上一次运行的临时数据。
2. **初始化：** 载入关卡和角色基础配置；应用玩家永久强化；初始化局内材料、技能装备栏、技能背包、连锁状态、本局货币、击败数和计时器。
3. **开始运行：** 关卡与战斗行为以关卡 / 战斗策划案为准。
4. **结束判定：** 玩家死亡进入失败；最终 BOSS 被击败进入胜利。禁止同一帧重复进入胜利与失败结算。
5. **冻结本局：** 停止敌人、技能、掉落物、生成器和本局计时；记录本局结果统计。
6. **结算货币：** 把本局已收集货币加入局外余额并写入玩家存档；成功保存后才显示结算界面。
7. **清理局内临时数据：** 清空剩余素材、技能栏、技能背包、连锁运行数据与本局计时；已发现配方记录与局外成长数据不清除。
8. **显示结算：** 仅显示胜负、本局获得货币、战斗时长、击败敌人数。
9. **返回据点：** 玩家点击确认后回到据点固定出生点并恢复角色操作。

## 6.4 结算界面信息

| 字段 | 规则 |
|---|---|
| 本局结果 | 显示「胜利」或「失败」 |
| 本局获得货币 | 显示本局已收集且已结算的货币总量 |
| 战斗时长 | 使用实际推进的游戏内生存计时，不计算 UI 暂停时间 |
| 击败敌人数 | 按成功进入死亡 / 击败状态的敌人实例计数；同一敌人只统计一次 |
| 确认按钮 | 点击后关闭结算界面并返回据点 |

不在 Demo 结算界面展示素材统计、技能成长详情、永久强化前后变化或历史记录，除非后续明确扩大范围。

# 7. 局内资源、货币与掉落物管理

## 7.1 两类局内资源

| 资源 | 来源 | 拾取方式 | 用途 | 结束处理 |
|---|---|---|---|---|
| 炼金素材 | 普通怪物可掉落普通素材；精英怪宝箱提供其专属材料及额外普通材料 | 进入吸取范围后自动拾取；宝箱靠近自动开启 | 局内配方尝试与技能制作 | 本局结束全部清空，不转入局外库存 |
| 局内货币 | 普通怪物与精英怪可掉落 | 进入吸取范围后自动拾取 | 本局累计并于结束时转为局外货币 | 正常胜利或失败结束时结算到账；已收集部分保留 |

## 7.2 掉落物生命周期

- 地面货币与普通素材不会按时间自动消失，直到被拾取或本局结束。
- 普通素材的库存按素材 ID 堆叠，不限制素材种类的槽位；同一种素材数量可持续增加。
- 精英怪必定掉落宝箱；宝箱进入玩家自动开启范围后立即触发奖励结算，不要求按交互键。
- 精英宝箱奖励由掉落配置决定，包括对应精英的专属材料和额外普通材料；奖励直接进入素材库存，不生成需要再次拾取的独立袋子。
- 最终 BOSS 当前不掉落宝箱或炼金材料；其胜利奖励以结束本局和结算为主。
- 拾取范围、单次奖励数量、掉率、素材类型等均由关卡 / 掉落配置提供，不在系统通用代码中写死。

## 7.3 货币结算规则

- 本局货币只记录已被玩家自动吸取的数量；尚在地面未吸取的货币不计入最终结算。
- 胜利和失败都执行同一货币结算流程。
- 结算金额写入局外账户前，先构造待提交的新玩家进度数据并尝试保存；成功后才确认新余额并显示结算界面。
- 如果保存失败，不覆盖原有效存档；保留当前待结算金额在内存中，显示明确错误与「重试保存」操作，不得让玩家误以为货币已永久到账。
- 本次 Demo 不保存可继续运行的战斗状态。若应用在正常结算前异常关闭，本局不能恢复；这属于 Demo 简化项，若后续要求异常退出也保留已收集货币，需要另行实现运行中货币恢复日志。

# 8. 局内炼金与配方匹配

## 8.1 设计目标

局内炼金是玩家使用本局素材尝试组合、发现配方并获得自动战斗技能的核心系统。它需要同时支持自由试验与已知配方快速制作：玩家可以手动投入素材，也可以在图鉴中选择已发现配方并自动填入素材。

## 8.2 入口与暂停

- 玩家在战斗中可以随时打开炼金界面。
- 打开炼金、图鉴、技能背包或其他局内系统界面时，整个战斗模拟与所有游戏内计时暂停：玩家和敌人移动、攻击、技能冷却、生成器、BOSS 预警、接触伤害计时、掉落物运动等均冻结。
- UI 动画、鼠标反馈与暂停菜单动画使用不受游戏暂停影响的 UI 时间。
- 界面之间切换（例如图鉴选择配方后进入炼金界面）不应短暂解除暂停；仅当所有阻塞式局内界面关闭后恢复游戏。

## 8.3 素材选取规则

- 玩家可以自由选择当前库存持有的素材种类与数量。
- 允许一次投入多个相同素材。
- 配方校验只检查素材种类与所需数量，不检查投入顺序。
- 同类素材在库存中堆叠显示；UI 应展示库存数、已选数量与剩余数量。
- 不限制素材种类的库存槽位，也不为每种素材创建单独的背包格数上限。
- 提交前若选中的任一种素材数量超过当前库存，禁止提交并提示素材不足；不消耗素材。

## 8.4 合成流程

1. 打开炼金界面，读取当前素材库存、技能装备栏、技能背包和技能等级。
2. 玩家选择素材组合。
3. 点击「尝试合成」后，对所选素材做存在性与数量校验。
4. 若素材选择本身不合法（例如数量超过库存），不执行合成、不扣除素材。
5. 若组合没有匹配任何有效配方，立即扣除本次投入的全部素材，显示「配方未发现」，不产生技能。
6. 若组合匹配有效配方，则先检查技能是否已满级，以及新技能是否存在可存放位置。
7. 若命中制作拦截条件（技能已满级；或新技能需要新实例但装备栏和技能背包均满），禁止消耗素材，并显示对应原因。
8. 若允许制作，立即扣除配方所需素材；若配方首次被玩家成功制作，则加入已发现配方记录并尝试自动保存。
9. 新技能若技能栏有空位，自动装备并立即参与战斗；若技能栏已满但技能背包有空位，则进入技能背包，不参与战斗。
10. 若配方产物是玩家已经拥有的技能（无论在装备栏还是技能背包），不创建重复实例，直接升级现有技能。
11. 显示结果反馈，并刷新素材、技能等级、技能栏与背包 UI。

## 8.5 消耗规则与拦截条件

| 情况 | 是否扣除素材 | 结果 |
|---|---:|---|
| 素材选择数量超出库存 | 否 | 提示素材不足，留在炼金界面 |
| 有效配方，技能未满级，且有空间 | 是 | 制作成功；新技能装备 / 入背包，或已有技能升级 |
| 无效素材组合 | 是 | 不生成技能，提示「配方未发现」 |
| 匹配到已满级技能 | 否 | 提交前拦截，提示「技能已满级」 |
| 新技能需要新实例，技能栏与技能背包均满 | 否 | 提交前拦截，提示技能空间不足 |
| 已存在同名技能且尚未满级 | 是 | 强化原有技能，不额外占用空间 |

> **重要区分：**「配方没有被玩家发现」不等于「系统不存在该配方」。有效配方由内容数据定义；玩家通过成功制作首次发现。无效组合在素材扣除后不产生技能。

## 8.6 首次发现配方的保存

- 配方首次成功制作后，立即把其 `RecipeId` 写入玩家进度中的已发现集合，并触发自动保存。
- 若此时保存失败，不能覆盖原有效存档；本局内仍保留成功制作结果与内存中的发现记录，并提示保存异常。后续任一关键保存成功时应再次包含尚未持久化的发现记录。
- 失败结束不会回滚已经发现并成功写入存档的配方。

# 9. 技能装备栏、技能背包与技能升级

## 9.1 两类技能容器

- **技能装备栏：** 当前正在使用的技能集合。只有其中的技能会参与自动攻击、技能冷却与连锁反应判定。
- **技能背包：** 存放暂时未装备的技能。背包中的技能不攻击、不参与连锁，但玩家可在战斗中随时打开背包并替换装备。
- 两者分别拥有固定格数上限；具体格数通过配置控制。
- **建议 Demo 默认值（可调整）：** 装备栏 6 格、技能背包 12 格。6 格参考 Survivors-like 游戏常见的有限主动武器位思路，背包作为项目独有的储备空间；以上数值仅是制作起点，不是项目方已确认的最终平衡值。

## 9.2 新技能归属

| 条件 | 制作成功后的处理 |
|---|---|
| 产物技能已经在装备栏中 | 升级现有装备技能 |
| 产物技能已经在技能背包中 | 升级背包中的既有技能，不生成新实例 |
| 产物是新技能且装备栏有空格 | 自动装备 |
| 产物是新技能且装备栏满、背包有空格 | 放入技能背包 |
| 产物是新技能且装备栏与背包都满 | 提交前拦截，不消耗素材 |

## 9.3 重复制作与技能等级

- 每种技能的最大等级独立配置。
- 重复制作已有技能直接提升该技能等级，不创建同名新实例。
- 每次提升的属性和增量在 `SkillDefinition` 中配置；本文不指定具体伤害或属性值。
- 达到技能上限后，禁止再次制作该技能并显示「技能已满级」，本次不消耗素材。
- 当某技能升级时，即使其位于技能背包中也可升级。

## 9.4 技能替换流程

1. 玩家在技能背包界面选中待装备技能。
2. 若装备栏有空位，显示「装备」操作；确认后从背包移至装备栏。
3. 若装备栏已满，要求选择一个当前装备技能作为替换目标。
4. 替换时必须由玩家明确选择被替换技能的处理方式：放回背包或移除。
5. 若选择放回背包，系统先验证交换事务在空间上可成立，再一次性完成两者交换，避免中途出现技能丢失。
6. 若选择移除，提示即将永久移除当前单局中的该技能，确认后执行。
7. 若玩家取消操作，不改变装备栏与背包。
8. 装备变动完成后重新计算所有连锁配方的激活状态。

## 9.5 技能背包边界

- 背包容量已满时，不得把新技能覆盖到任意旧技能上。
- 不允许无提示地丢弃技能。
- 角色死亡或最终 BOSS 被击败后，技能装备栏与技能背包的本局数据均清空。
- 本 Demo 不需要把技能背包变成局外仓库；技能不跨局保存。

# 10. 炼金连锁反应系统

## 10.1 设计目的与作用边界

炼金连锁反应是在玩家装备指定技能组合后激活的自动效果。连锁配方的触发时机、目标搜索与冷却独立于基础技能攻击时间。连锁效果只需与当前技能装备栏建立依赖；技能背包中的技能不能满足激活条件。

## 10.2 激活规则

- 每套连锁配方配置一组必需技能 ID。
- 当前技能装备栏同时包含该配方要求的全部技能时，该连锁处于激活状态。
- 缺少任一所需技能时，连锁不可触发。
- 不同连锁配方可同时激活、同时执行，且各自独立管理冷却与本局触发次数，不需要全局优先级。

## 10.3 触发时机和冷却

- 连锁自身冷却结束后自动尝试触发，不等待基础技能发动攻击或命中。
- 每套连锁配方独立配置冷却时间与本局允许触发次数。
- 连锁触发成功时，消耗一次本局触发次数，并开始 / 重置该连锁的冷却计时。
- **建议默认次数规则：** 触发次数只在效果真正开始执行时消耗；若该连锁配置为有限次数，次数耗尽后本局不再触发。解除再装备所需技能不会重置已消耗次数，避免通过反复换装绕过限制。
- **建议默认不限次表示：** `MaxTriggersPerRun = 0` 表示不限制本局触发次数；正整数表示本局最多成功执行的次数。每条连锁仍需有 `CooldownSeconds` 配置。

## 10.4 目标选择与搜索距离

- 每套连锁配方独立配置最大目标搜索距离。
- 连锁进入触发判定时，在合法敌人中选取距离玩家最近的敌人；最近距离需不超过该连锁配置的搜索距离。
- 若多个敌人距离完全相同，按稳定的敌人实例 ID 作第二排序键，确保结果可复现。
- 目标距离以玩家与敌人配置的目标锚点之间的世界坐标距离计算；默认使用二维距离，不纳入 Z 轴高度。
- 是否允许无视遮挡由连锁效果类型决定。若没有单独配置，则沿用战斗系统中技能对应的目标与障碍规则，不额外创建冲突规则。

## 10.5 无有效目标时的处理

项目方已确认该规则由每套连锁配方独立配置。为保证程序实现一致，建议 `NoTargetBehavior` 支持以下枚举：

| 配置值 | 行为 | 冷却 / 次数处理 |
|---|---|---|
| `SkipAndRestartCooldown` | 本次不产生连锁效果，跳过本次机会 | 重新开始该连锁冷却；不消耗成功触发次数 |
| `WaitForTarget` | 保持就绪状态，持续检查是否有敌人进入有效范围 | 冷却保持为就绪；出现目标后立即触发并消耗次数 |
| `ExecuteWithoutEnemy` | 按该连锁配置的无目标效果执行方式运行（例如以玩家位置为中心） | 只有确实开始执行效果时才消耗次数，并启动冷却 |

`ExecuteWithoutEnemy` 只有在对应连锁定义了不依赖敌人目标的执行位置 / 执行函数时才能使用；若未配置，则数据校验应回退为 `SkipAndRestartCooldown` 并在开发日志报错。

## 10.6 连锁中断与重新激活

- 若连锁所需技能被玩家移出技能装备栏，已开始执行的连锁效果允许完成；效果结束后停止后续触发。
- 该连锁的冷却和本局剩余触发次数独立保留；移除技能不会重置冷却或次数。
- 再次装备齐所需技能后自动重新激活，并沿用原有冷却状态。若冷却已结束且所选无目标模式允许立即执行，则按该配方规则继续。
- 每套连锁独立保存本局运行状态：是否激活、是否执行中、剩余冷却、成功触发次数 / 剩余次数和上一次目标（仅在该效果需要时记录）。
- 本局结束后清空所有连锁运行状态，不写入玩家进度存档。

# 11. 局外永久强化系统

## 11.1 入口与范围

- 局外永久强化通过主菜单的「局外成长」快捷入口进入，也能通过据点中的主炼金设施进入。
- 两个入口调用同一套强化业务与同一界面组件，避免价格、等级或余额显示不一致。
- 当前 Demo 只确认永久数值强化，不额外制作新技能解锁、角色解锁、关卡解锁或其他内容解锁系统。
- 永久强化只能在局外购买；进入战斗后不能更改强化等级。

## 11.2 强化数据

每项强化至少包括：唯一 ID、名称、说明、最大等级、每一级独立价格、每一级效果、效果目标属性、数值叠加方式、生效时机、排序和可见条件。实际强化项、价格、数值与成长公式由数值 / 内容配置填入，不在本系统案中虚构。

## 11.3 强化等级与价格规则

- 每项强化可重复升级，最大等级由该项配置控制。
- 每一级价格独立配置，不强制按固定比例增长。
- 达到最大等级时禁止购买，按钮显示「已满级」。
- 货币不足时禁止购买，并提示所需货币与当前余额。
- 玩家必须主动选中强化项目并点击购买，不自动购买或自动升级。

## 11.4 购买流程

1. 打开强化界面，读取当前余额、各强化等级与配置价格。
2. 玩家选择一项强化并点击「购买 / 升级」。
3. 弹出二次确认窗口，显示强化名称、当前等级、目标等级、费用和购买后的效果说明。
4. 玩家取消时不扣除货币、不修改等级。
5. 玩家确认后重新检查：强化是否已满级、余额是否足够、价格与等级数据是否合法。
6. 检查通过后，在临时进度副本中扣除货币并提升等级，再写入主存档。
7. 保存成功后提交更改、更新界面、显示购买成功反馈；保存失败则保留原有效存档，将内存中的余额与等级回滚到购买前，并提示保存失败。
8. 重新打开强化界面或从另一个入口打开时，必须读取最新的权威玩家进度，不能保留旧 UI 缓存。

## 11.5 强化效果生效

- 强化永久生效，后续每局持续生效。
- 各强化项可以配置自己的效果类型与应用规则；强化等级是权威数据，玩家基础战斗参数由“基础配置 + 当前强化等级的效果汇总”在每局初始化时计算。
- **建议默认生效时机：** 购买完成后立即更新局外显示；进入下一局时统一应用到战斗角色。由于购买只允许局外进行，本局战斗不需要热更新强化属性。
- 程序不得为每个强化项编写独立硬编码逻辑；统一通过效果定义和属性修正器应用配置。

# 12. 配方图鉴系统

## 12.1 访问入口

- 局外：主菜单快捷入口、据点中的独立图鉴设施均可打开图鉴；仅查看配方和解锁记录，不提供制作功能。
- 局内：玩家可以打开图鉴查看配方；已发现配方可选中并自动填入炼金界面所需素材。
- 局内打开图鉴会暂停整个战斗模拟与所有游戏内计时。

## 12.2 配方信息显示

| 配方状态 | 展示内容 | 禁止展示 / 行为 |
|---|---|---|
| 已发现 | 产物名称、图标、完整素材种类与数量、可用的配方分类 / 标签 | 不应隐藏已发现配方的需求明细 |
| 未发现 | 产物线索，以及允许展示的模糊说明 | 隐藏精确素材清单与数量；不能让 UI 直接泄露配方答案 |

- 配方的存在与线索来自内容数据；发现状态来自玩家存档中的 `DiscoveredRecipeIds`。
- 首次成功制作后永久记录发现状态，即使本局失败也不撤销。
- 图鉴的总配方数量来自当前版本中启用的图鉴数据，不计入禁用内容或仅用于开发测试的配方。

## 12.3 图鉴浏览默认方案

为避免本次 Demo 继续等待分类方案，建议采用以下默认交互（可调整）：

- 基础筛选：全部 / 已发现 / 未发现。
- 搜索：支持按可见产物名称进行文本搜索；未发现条目仍只能用其可见名称或线索搜索，不因搜索而显示隐藏素材明细。
- 分类：优先使用配方数据中配置的产物类型或标签；若 Demo 内容尚未配置标签，则只提供基础筛选，不制作空分类页签。
- 排序：已发现条目优先、未发现条目随后；同一状态内按 `DisplayOrder` 再按 `RecipeId` 稳定排序。
- 进度：显示总体发现进度 `已发现数量 / 当前有效配方总数`；暂不强制展示每种分类的百分比。

以上为系统案补充的可执行默认方案，不是此前对话中已逐项确认的玩法要求。

## 12.4 已发现配方自动填料

- 仅在局内炼金流程中可将图鉴配方转换为素材选择。
- 选择已发现配方时，先检查库存是否具备完整所需数量；足够时，以该配方所需素材组合替换当前已选择的素材，而不是将新配方简单叠加到已有选择上。
- 若素材不足，保持当前选择不变，显示缺少的素材种类与数量；不扣除素材。
- 局外图鉴没有「制作」按钮，也不允许将局外任何资源兑换为局内技能。

# 13. 存档、自动保存、备份、恢复与重置

## 13.1 存档结构

- 游戏使用单一玩家进度存档，不提供多存档槽位和手动存档操作。
- 关键数据变更时自动保存。
- 使用主存档与备用存档，自动维护有效备份。
- 游戏设置保存在独立设置文件中；重置玩家进度时保留设置。
- 本 Demo 不保存正在进行的整局战斗状态，不提供中途继续 / 读档战斗功能。

## 13.2 玩家进度保存触发点

至少在以下场景触发保存：

- 永久强化购买成功；
- 首次成功制作并发现新配方；
- 胜利 / 失败时，把本局已收集货币正式结算进局外账户；
- 玩家主动重置游戏进度；
- 为修复格式 / 迁移版本而必须写回的存档升级流程。

日常素材数量、技能栏、技能背包、连锁冷却与本局计时不触发玩家进度保存，因为它们属于临时局内数据。

## 13.3 文件建议

建议在 Unity `Application.persistentDataPath` 下使用独立文件：

- `player_progress.json`：当前玩家长期进度；
- `player_progress.bak.json`：最近一次已验证的有效备份；
- `player_progress.tmp.json`：写入中的临时文件；
- `settings.json`：独立设置文件；
- `reset_in_progress.flag`：进度重置事务标记（仅在重置过程中存在）。

文件名与路径属于建议实现，可按项目命名规范调整，但职责必须保持分离。

## 13.4 玩家进度内容

- 存档 Schema 版本；
- 当前局外货币余额；
- 永久强化 ID → 等级映射；
- 已发现配方 ID 集合；
- 必要的版本迁移字段与校验信息。

不得把 UI 状态、打开过哪个界面、敌人列表、局内材料或技能运行时对象引用直接序列化进玩家长期存档。

## 13.5 安全保存流程

1. 对当前权威进度创建不可变快照。
2. 序列化到临时文件，完成写入并刷新文件缓冲。
3. 重新读取临时文件并执行基本结构 / 校验验证。
4. 在新文件确认有效之前，不得删除或覆盖当前有效主存档。
5. 将当前有效主存档复制 / 轮换为备用存档，再以安全替换方式提交新主存档。
6. 重新读取主存档确认提交成功后，才把本次变更标记为已持久化。
7. 若任一步失败，保留至少一份原有效存档，清理可安全清理的临时文件，记录错误并提示玩家。

保存操作应串行执行，避免购买强化、发现配方、货币结算或重置同时写文件导致覆盖竞争。

## 13.6 保存失败规则

- 保存失败时必须保留原有有效存档，并提示玩家。
- 强化购买采用事务回滚：保存失败时不扣永久货币、不提高永久强化等级。
- 单局货币结算在写入成功前保留为待提交状态；显示保存失败提示并提供重试。只有成功写入后才显示正式结算界面。
- 配方制作发生在战斗流程中。若首次发现记录保存失败，保留当前局内制作结果与内存中的发现状态，显示存档警告并在后续关键保存时再次写入发现记录；不得因保存失败而把已扣素材和已生成技能静默回滚。若程序随后异常终止，尚未持久化的数据可能丢失，这属于磁盘写入失败的剩余风险。
- 设置保存失败时保留上次已保存的设置数据，并提示玩家；若当前设置无法持久化，建议回退到上次有效设置，避免界面显示与重启后状态不一致。

## 13.7 存档损坏恢复

当主存档存在但读取 / 校验失败，或主存档缺失但检测到备用存档时，不得静默覆盖损坏文件。显示清晰的恢复界面，由玩家选择：

1. **从备用存档恢复：** 仅当备用文件校验有效时提供；将损坏主存档保留为诊断文件，再将备用内容恢复为主存档。
2. **重新开始（创建全新玩家进度）：** 清空玩家货币、永久强化与配方图鉴记录，保留游戏设置；该操作需再次确认。
3. **退出游戏：** 不修改原有损坏文件，不自动创建新存档。

若主存档损坏且备用存档也不可用，只显示「重新开始」与「退出游戏」选项，并明确告知无法恢复旧进度。

## 13.8 主动重置游戏进度

- 玩家可主动重置全部玩家进度。
- 需要二次确认：第一次点击重置后展示风险说明；玩家再次明确确认后才开始事务。
- 重置内容：局外货币归零、所有永久强化等级恢复初始、已发现配方记录清空，以及未来任何属于玩家进度文件的解锁 / 进度字段恢复初始。
- 保留 `settings.json` 中的设置，包括画面、音量、自定义键位与语言选择字段。
- 主存档和备用存档中的玩家进度必须一并重置，不能留有旧进度作为可恢复备份。
- 实现建议：先写入 `reset_in_progress.flag`，再准备一份默认玩家进度并校验；依次更新主存档与备用存档；确认两者均为新进度后删除标记。启动时如发现重置标记，必须继续完成重置事务，不能把旧备用存档恢复回来。
- 若重置事务失败，不提示重置成功；进入错误提示，保留可恢复的原进度或停留在恢复流程中，避免出现主存档已清空但备用存档仍旧的半完成状态。

# 14. 游戏设置系统

## 14.1 已确认范围

Demo 设置包含：画面设置、音量设置、操作设置。语言底层架构需要可扩展，但 Demo 暂时只开放简体中文。设置独立保存，并提供恢复默认设置功能。

## 14.2 画面设置

**建议 Demo 实现的最小字段：** 分辨率、窗口模式（窗口 / 无边框窗口 / 全屏，具体模式由 Unity 与目标系统能力决定）、垂直同步或帧率限制。若团队制作成本有限，可以只实现分辨率与窗口模式，但设置 UI 不应出现无效选项。

- 更改分辨率 / 窗口模式后立即预览新设置；对可能导致黑屏或不可见的显示模式变更，使用限时确认：玩家在时限内确认则保存，未确认则自动恢复旧设置。
- 不在当前 Demo 增加图形质量分级、动态分辨率或高级渲染选项，除非画面性能测试需要。

## 14.3 音量设置

- 提供主音量、音乐音量、音效音量三个滑块。
- 子音量与主音量共同决定输出音量；滑块范围建议为 0–100%，对应线性或项目音频混音曲线由音频实现确定。
- 修改时即时预览并自动保存；音量为 0 时完全静音。

## 14.4 操作设置与默认键位

| 动作 | 建议默认键位 | 说明 |
|---|---|---|
| 向上 / 下 / 左 / 右移动 | W / S / A / D | 支持重映射；斜向速度归一化由战斗控制器负责 |
| 闪避 / 短冲刺 | Space | 支持重映射 |
| 据点设施交互 | E | 支持重映射 |
| 返回 / 关闭界面 | Esc | 建议保留为不可重映射的系统返回键 |
| 菜单鼠标操作 | 鼠标左键 | 点击 UI；鼠标指向技能仍按战斗策划规则处理 |

- 自定义键位冲突时，显示冲突动作并要求玩家决定；Demo 默认不允许两个关键动作映射到同一个按键，避免一个输入触发多项行为。
- 绑定录入期间按 Esc 取消此次重绑定，不把 Esc 保存为新的动作键。
- 提供单个动作恢复默认与全部恢复默认两种能力是可选项；本次最低验收要求提供「恢复全部默认设置」。
- 修改键位后立即刷新输入映射与 UI 提示，不需要重启游戏。

## 14.5 语言架构

- Demo 实际开放语言仅简体中文。
- UI 文本、提示文本、错误信息与图鉴线索均通过本地化文本 ID / 表驱动，不把大量中文文案散落在代码中。
- 语言设置字段与本地化加载器预留多语言扩展能力；当前设置界面不必显示语言选择控件，避免出现只有一个选项的无用菜单。

## 14.6 恢复默认设置

- 点击后弹出确认提示；确认后重置画面、音量和操作配置为默认值，立即应用并保存。
- 恢复默认设置不影响货币、永久强化、已发现配方或任何玩家进度。
- 如默认画面参数导致显示异常，使用同样的限时确认与恢复逻辑。

## 15.2 暂停与模态界面规则

- 所有战斗中的系统 UI 统一通过一个 `PauseCoordinator` / 暂停服务控制，不允许每个界面各自直接设定或恢复时间。
- 首个阻塞式系统界面打开时获取暂停令牌；所有游戏模拟与游戏内计时暂停。
- 多个界面之间切换时，暂停令牌保持有效；仅当所有阻塞式界面关闭时才恢复游戏。
- 关闭设置但仍处于暂停菜单时，不恢复战斗；玩家明确选择「继续」后才恢复。
- UI 自身动画使用 unscaled time；战斗模拟、技能冷却、敌人行为、掉落物运动、生成器、BOSS 事件和游戏计时使用受暂停控制的游戏时间。

最低限度实现以下明确提示，避免只通过按钮灰态表达错误：

- 「配方未发现」；
- 「技能已满级」；
- 「技能栏与技能背包已满，无法制作新技能」；
- 「素材不足：需要 X，当前 Y」；
- 「货币不足：需要 X，当前 Y」；
- 「已满级」；
- 「保存失败，原有有效存档已保留」；
- 「存档损坏，请选择恢复方式」；
- 「重置游戏进度后，货币、永久强化与配方图鉴将被清除，设置会保留」；
- 「与该按键冲突的动作是……」；
- 「当前没有足够素材，无法自动填入该配方」。

错误信息应同时有玩家可理解的本地化文案和程序日志错误码。日志不得将内部异常堆栈直接呈现给普通玩家。

## 16.9 战斗启动扩展对象 `RunLaunchOptions`

- `startingSkillIds`（默认空数组）；
- `loadoutModifiers`（默认空数组）；
- `futureOptionPayload`（未来扩展对象，不要求当前存档持久化）。

当前版本通过统一战斗启动方法传递默认对象，确保后续加入开局配置时不需要重写加载流程。

# 17. Unity 程序模块与职责边界

## 17.1 建议模块拆分

| 模块 | 核心职责 | 不负责的内容 |
|---|---|---|
| `GameFlowController` | 主菜单、据点、关卡加载、结算返回的场景流转 | 不直接计算配方或强化价格 |
| `HubInteractionController` | 交互范围、提示、交互输入与打开设施 UI | 不维护永久进度 |
| `RunSessionManager` | 初始化 / 结束单局、持有本局临时数据、统计战斗时长与击败数 | 不承担文件存储 |
| `PauseCoordinator` | 统一管理暂停令牌及游戏时间冻结 | 不实现具体界面内容 |
| `MaterialInventoryService` | 素材堆叠、增加、扣除、数量校验 | 不决定技能效果 |
| `AlchemyCraftingService` | 配方匹配、制作前校验、材料消耗、结果生成 | 不处理界面动画 |
| `RecipeBookService` | 配方定义检索、已发现状态、图鉴查询与自动填料请求 | 不独立保存文件 |
| `SkillLoadoutService` | 装备栏、背包、容量、重复技能升级、替换事务 | 不负责技能攻击逻辑本体 |
| `ChainReactionService` | 激活条件、独立冷却、目标搜索、次数、无目标与中断规则 | 不依赖基础技能攻击事件触发 |
| `MetaUpgradeService` | 强化购买验证、费用、等级、效果计算 | 不直接写 JSON 文件 |
| `CurrencyService` | 本局货币累计、结算金额计算及局外余额更新请求 | 不持有存档文件操作代码 |
| `SaveService` | 玩家进度与备用存档的序列化、校验、提交、恢复、重置 | 不决定 UI 业务流程 |
| `SettingsService` | 设置加载、应用、校验与独立保存 | 不修改玩家成长数据 |
| `UIFlowController` | UI 打开关闭、面板切换、按钮防重复触发、提示 | 不复制系统校验逻辑 |

## 17.2 业务与 UI 分离

- UI 只采集操作并展示服务返回结果，不在按钮事件中直接修改货币、配方或强化等级。
- 所有扣除素材、扣除永久货币、升级技能、交换技能和写存档的操作都通过对应 Service 进行。
- 业务返回统一结果类型，例如 `Success`、`InsufficientMaterial`、`RecipeNotFound`、`SkillMaxLevel`、`InventoryFull`、`SaveFailed`，UI 再将其映射到本地化提示。
- 所有配置在进入运行前做数据校验，避免运行时才发现缺少技能、重复配方 ID 或负数冷却。

## 17.3 数据资产建议

静态内容推荐使用 ScriptableObject 或项目现有的表格导入方案；玩家存档只存稳定 ID 与运行必要数值，不存 ScriptableObject 引用。运行时对配置做只读缓存，存档和 UI 不应直接持有 Unity 场景对象引用。

# 18. 异常处理与边界规则

| 异常场景 | 系统行为 |
|---|---|
| 主存档与备用存档都不存在，属于首次启动 | 创建初始玩家进度和默认设置，然后进入主菜单 |
| 主存档不存在但备用存档有效 | 进入恢复界面，提供从备用存档恢复或退出；不得直接创建空存档覆盖恢复机会 |
| 主存档格式有效但字段缺失 | 按 Schema 迁移 / 默认值补齐；无法安全迁移时进入恢复界面 |
| 主存档损坏、备份有效 | 提示玩家选择恢复方式，不自动覆盖损坏文件 |
| 主存档和备份都损坏 | 允许重新开始或退出；不得假称能够恢复旧数据 |
| 保存过程失败 | 保留原有有效存档并提示；关键事务不得静默宣告成功 |
| 玩家余额低于当前强化价格 | 阻止购买并展示所需 / 当前金额 |
| 强化等级达到上限 | 按钮显示已满级，不执行购买 |
| 有效配方产物技能已满级 | 不消耗素材，不执行升级 |
| 新技能没有装备栏或背包空间 | 不消耗素材，不生成技能 |
| 无效组合 | 消耗投入素材，不产出技能，显示「配方未发现」 |
| 玩家退出 / 切换图鉴时选料状态存在 | 取消未提交的选择不会扣除素材；除非已经点击「尝试合成」 |
| 替换技能时背包空间不足 | 不执行部分交换；整个替换事务成功或失败，不丢失技能 |
| 连锁指定技能被卸下 | 已运行效果完成，之后停止再次触发；重新装备后按原冷却恢复 |
| 多套连锁同时就绪 | 各自独立触发，不设全局互斥或优先级 |
| 交互键在多个设施范围内 | 选择最近的可交互设施；同距使用稳定排序 |
| 关卡进入按钮被连续点击 | 只允许一次场景加载与单局初始化 |
| 同时满足胜利和失败事件 | 只允许首先成功提交的终局状态生效；后续结束事件忽略 |
| 打开战斗系统 UI 时其他系统计时器正在运行 | 所有游戏模拟时间冻结，UI 切换期间保持冻结 |

# 19. Demo 验收标准

下表作为基本功能验收，不替代数值平衡测试。测试中应同时检查 UI 表现、业务返回值和存档数据。

## 19.1 主流程与据点

- [ ] 启动后显示独立主菜单，列出开始游戏、局外成长、配方图鉴、游戏设置、退出游戏。
- [ ] 点击开始游戏进入独立俯视角据点，玩家可自由移动。
- [ ] 靠近主炼金设施并按交互键可打开永久强化界面。
- [ ] 靠近图鉴设施并按交互键可打开图鉴；主菜单入口也可打开同一业务界面。
- [ ] 靠近战斗出口并按交互键可打开关卡选择界面，Demo 只有一个可选关卡。
- [ ] 单局正常结束后显示结算；点击确认后返回据点并可继续移动。

## 19.2 炼金与技能

- [ ] 素材按种类数量堆叠，不因素材种类增加而占用有限格位。
- [ ] 玩家可重复投入同种素材，配方匹配忽略投入顺序。
- [ ] 有效配方制作后立即扣材，并在装备栏有空位时自动装备技能。
- [ ] 装备栏满但技能背包有空间时，新技能进入背包并且不参与战斗 / 连锁。
- [ ] 重复制作装备栏或背包中已有技能时升级原技能，不创建重复实例。
- [ ] 已满级技能的制作请求被拦截且素材不扣除。
- [ ] 装备栏和背包均满时，新技能制作被拦截且素材不扣除。
- [ ] 无效组合扣除投入素材，不产出技能并显示「配方未发现」。
- [ ] 从局内图鉴选中已发现配方且素材足够时，所选素材被自动替换为配方需求；素材不足时不扣材并显示缺少项。
- [ ] 首次成功制作的配方加入永久发现记录；单局失败后仍保留已保存记录。

## 19.3 连锁反应

- [ ] 装备栏齐指定技能时连锁激活；背包内技能不计入条件。
- [ ] 连锁冷却结束时自动尝试触发，不依赖基础技能当前是否攻击。
- [ ] 每套连锁独立冷却、目标范围与无目标策略。
- [ ] 搜索范围内存在多个敌人时选择最近敌人；超出最大距离的敌人不作为该连锁目标。
- [ ] 多套连锁同时就绪时允许并行启动。
- [ ] 所需技能被卸下时当前效果按规则完成，之后不再触发；重新装备后不重置冷却与已消耗次数。
- [ ] 有限触发次数耗尽后本局不再启动该连锁；无限次配置可在冷却后重复执行。

## 19.4 永久强化与货币

- [ ] 玩家可以通过主菜单和据点设施进入同一强化界面。
- [ ] 每一级强化使用配置中独立价格。
- [ ] 购买前有二次确认；取消后余额与等级均不变。
- [ ] 余额不足时显示所需金额和当前余额；满级时显示「已满级」。
- [ ] 购买成功后即时保存并刷新余额与等级。
- [ ] 保存失败时回滚未持久化购买，并保留原存档。
- [ ] 胜利和失败都能将已收集局内货币结算至局外账户；结算 UI 在货币写入成功后显示。

## 19.5 图鉴、设置与存档

- [ ] 局外图鉴只能查看，不允许制作。
- [ ] 未发现配方显示线索、不显示完整素材需求；已发现配方显示完整素材种类与数量。
- [ ] 图鉴发现记录在重启游戏后仍存在。
- [ ] 设置包含画面、音量、操作；当前语言开放简体中文，并通过文本 ID / 本地化表管理。
- [ ] 自定义键位、设置修改和恢复默认设置后能正确应用并在重启后保持。
- [ ] 单存档自动保存并维护有效备用存档；临时文件写入失败不破坏原有效存档。
- [ ] 主存档损坏时展示恢复选项，不静默覆盖原文件。
- [ ] 重置进度经过二次确认，重置货币 / 强化 / 配方记录并同步更新主、备份存档，设置保留。

## 19.6 暂停行为

- [ ] 局内打开炼金、图鉴、技能背包、设置等阻塞式系统 UI 时，生存计时、敌人、玩家战斗行动、技能冷却、生成器与所有游戏计时均冻结。
- [ ] UI 之间切换时保持暂停，不出现一帧恢复战斗的情况。
- [ ] 关闭暂停菜单中的设置不会自动恢复战斗；只有选择继续后才恢复。

# 20. 制作优先级与依赖关系

## 20.1 推荐实现顺序

1. **数据与存档基础：** 玩家进度模型、设置模型、主 / 备份存档、加载校验、保存失败处理。
2. **流程骨架：** 主菜单、据点、设施交互、关卡选择、战斗进入、单局结束、货币结算与返回据点。
3. **资源服务：** 局内素材堆叠、货币累计、拾取 / 宝箱奖励接口。
4. **炼金制作：** 配方匹配、消耗规则、无效组合、制作拦截、首次发现保存。
5. **技能管理：** 装备栏、背包、容量、重复技能升级、替换事务。
6. **永久强化：** 配置价格、等级上限、确认购买、属性效果应用与保存。
7. **图鉴：** 局内 / 局外入口、发现状态、线索、自动填料、搜索与进度展示。
8. **连锁反应：** 激活、目标搜索、独立冷却、次数、无目标模式、并行执行和卸装行为。
9. **设置与 UI 细化：** 画面、音量、键位、自定义与恢复默认。
10. **全流程测试：** 正常胜利、正常失败、保存失败、存档损坏、重置、满仓、满级和同时触发连锁。

## 20.2 主要依赖

- 炼金制作依赖素材库存、配方定义、技能定义与技能容量校验。
- 图鉴依赖配方定义与玩家已发现集合；自动填料额外依赖炼金界面和素材库存。
- 永久强化依赖局外货币、强化配置与玩家进度存档。
- 货币结算依赖单局统计、玩家进度和存档提交结果。
- 连锁依赖技能装备栏状态、目标搜索服务和统一战斗时间。
- 所有局内系统 UI 依赖统一暂停服务。

## 21.1 本次采用的建议默认方案

以下条目用于补全当前没有逐项确认、但程序需要统一实现的常规规则。它们可以在评审后调整：

|---|---|---|
