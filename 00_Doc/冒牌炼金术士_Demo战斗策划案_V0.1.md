# 1. 文档目的与范围

## 1.1 文档目标

本策划案用于将《冒牌炼金术士》Demo 已确认的战斗规则整理为可实现、可测试的需求。重点覆盖：

- 玩家移动、自动攻击、鼠标指向技能与闪避；
- 玩家生命值、接触伤害、主动攻击伤害、受伤无敌与闪避无敌；
- 普通近战怪物、普通远程怪物的行为差异；
- 精英怪的战斗定位与强力攻击预警；
- 最终 BOSS 双阶段、攻击选择与攻击命中规则；
- 远程投射物与不可穿越障碍物的交互；
- 暂停行为、Unity 模块划分、配置字段与验收用例。

## 1.2 本文覆盖

本文覆盖“战斗过程如何运行”和“程序如何判断攻击、受伤与状态切换”。关卡中普通怪物与精英怪的时间波次、地图生成、宝箱发放等规则以关卡策划案为准；本文件只引用与战斗直接相关的交互。

## 1.3 本文不冻结的内容

下列内容尚未由项目方确定，本文不擅自设计具体答案：

- 玩家最大生命值、移动速度、闪避距离及相关时间参数；

# 2. 战斗设计基线与术语

## 2.1 项目基础

| 项目 | 当前基线 |
|---|---|
| 玩家人数 | 单人 |
| 平台 / 引擎 | PC / Steam；Unity |
| 镜头视角 | 正俯视 2D |
| 核心类型 | Survivors-like 自动战斗 + 炼金技能构筑 |
| 玩家主动攻击 | 没有独立普通攻击，主要依靠技能造成伤害 |
| 玩家主动操作重点 | WASD 走位、Space 闪避、部分指向性技能的鼠标方向 |
| 敌人层级 | 普通怪物、精英怪、Demo 唯一最终 BOSS |
| Demo 最终 BOSS | 生存计时 5:00 开始预警，预警 10 秒，5:10 正式出现（游戏内有效时间） |

## 2.2 核心术语

| 术语 | 定义 |
|---|---|
| 接触伤害 | 玩家与怪物接触时触发的伤害；首次接触立即判定，持续接触时按固定间隔重复判定。 |
| 主动攻击伤害 | 怪物执行主动攻击招式时，通过该招式的攻击判定造成的伤害。 |
| 攻击实例 | 一次独立的攻击执行过程，用于记录该次攻击是否已经命中过玩家。 |
| 伤害区域 / Hitbox | 攻击生效时用于判断玩家是否处于伤害范围内的区域。 |
| 受伤无敌 | 玩家受到有效伤害后触发的短暂无敌状态。 |
| 闪避无敌 | 玩家执行 Space 冲刺 / 闪避时获得的短暂无敌状态。 |
| 强力攻击预警 | 强力攻击生效前向玩家提供的可识别提示。 |
| 可用 BOSS 招式 | 当前阶段允许使用、冷却已经结束的招式；额外条件若需存在，应在具体招式设计中另行确认。 |

# 3. 玩家操作与技能控制

## 3.1 输入规则

| 输入 | 已确认行为 | 待确认细节 |
|---|---|---|
| WASD | 控制玩家移动 | 移动速度、斜向移动是否归一化等数值 / 细节待确认。 |
| Space | 触发短距离冲刺 / 闪避，冲刺期间无敌 | 冲刺方向、距离、持续时间、冷却或次数限制待确认。 |
| 鼠标位置 | 决定部分指向性技能的释放方向 | 鼠标屏幕坐标转世界坐标的实现细节及鼠标位置无效时的处理待确认。 |
| 普通攻击键 | 不设置独立普通攻击 | 不适用。 |

## 3.2 自动技能规则

**已确认规则：**

1. 玩家没有独立普通攻击，主要依靠技能造成伤害。
2. 技能满足其冷却或触发条件后自动释放。
3. 默认自动攻击目标优先选择距离最近的敌人。
4. 对于指向性技能，技能仍可自动触发，但释放方向由鼠标位置决定；这不等同于玩家点击鼠标主动施法。

**规则整理：**

- 一般自动目标技能：在该技能可选目标中，优先选择距离最近的敌人。
- 鼠标指向技能：技能触发时，根据当前鼠标位置确定释放方向。
- 玩家是否可在技能执行时继续移动、自动目标技能的有效射程、无合法目标时的处理、技能冷却从何时开始计算，均为待确认项。

## 3.3 目标选择与方向

默认目标优先级是“距离最近的敌人”。具体技能的目标类型、射程、目标过滤条件尚未确定，因此不能默认所有技能都攻击最近单位，也不能默认所有技能都使用鼠标方向。

| 技能控制类型 | 触发方式 | 目标 / 方向规则 |
|---|---|---|
| 自动目标技能 | 满足冷却或触发条件后自动释放 | 默认优先选择距离最近的敌人 |
| 鼠标指向技能 | 满足冷却或触发条件后自动释放 | 按鼠标位置确定方向 |
| 其他特殊技能 | 待具体技能设计确定 | 待确认 |

# 4. 玩家生命、受伤与无敌规则

## 4.1 玩家受伤来源

目前明确存在以下伤害来源：

- 玩家与怪物接触产生的接触伤害；
- 怪物主动近战攻击产生的攻击伤害；
- 远程怪物投射物命中造成的攻击伤害；
- 精英怪与最终 BOSS 的攻击伤害。

各类伤害的具体数值、抗性、减伤、暴击或其他属性机制尚未确认，本文不定义相关公式。

## 4.2 受伤结算流程

**规则整理：**

1. 战斗系统产生一次伤害请求，记录伤害来源与所属攻击实例。
2. 检查玩家是否处于受伤无敌或闪避无敌状态。
3. 若任意一种无敌状态生效，本次伤害不扣除生命值。
4. 若均未生效，则按对应攻击的配置扣除生命值，并触发受击表现与受伤无敌。
5. 玩家生命值归零时，立即结束本局并进入失败结算。

> **待确认：** 受伤无敌期间被判定无效的接触伤害，是否仍消耗接触伤害计时；无敌结束时，持续接触是否立即造成一次伤害。该规则尚未确定，不能由程序自行选择最终行为。

## 4.3 受伤无敌与闪避无敌

| 规则项 | 已确认规则 |
|---|---|
| 受伤无敌触发 | 玩家受到有效伤害后触发。 |
| 闪避无敌触发 | 玩家执行 Space 闪避 / 冲刺期间触发。 |
| 计时方式 | 两种无敌独立计时，彼此不覆盖。 |
| 持续时间 | 两种无敌使用相同的持续时间配置值；具体时长待确认。 |
| 免疫范围 | 任意一种无敌生效时，免疫所有来源的伤害。 |
| 同时存在 | 两个计时器可以同时处于生效状态；只要其中任意一个有效，就不接受伤害。 |

**实现建议：** 用两个独立状态计时器 `HurtInvulnerabilityTimer` 与 `DodgeInvulnerabilityTimer`；它们读取同一配置值 `SharedInvulnerabilityDuration`。统一伤害入口只需判断任意计时器是否有效，避免不同攻击组件各自实现无敌判断。

## 4.4 接触伤害规则

**已确认规则：**

1. 玩家与怪物首次接触时触发一次接触伤害判定。
2. 在持续接触期间，按固定间隔继续判定接触伤害。
3. 接触伤害间隔为配置项，具体时间待确认。
4. 玩家处于任意无敌状态时，不会因该次伤害判定而扣除生命值。
5. 怪物处于主动近战攻击期间，只计算主动攻击伤害，不额外计算该怪物的接触伤害。

**待确认：** 接触结束后再次接触是否重置计时、无敌期间接触伤害计时是否继续运行，需由项目方进一步确认。

## 4.5 受击反馈

**已确认规则：** 玩家被攻击命中后播放受击表现，但不影响玩家移动。

受击表现的具体动画、闪烁、音效、屏幕反馈与时长尚未确认。不得在未确认的情况下增加强制硬直、击退或移动锁定。

## 4.6 玩家死亡

玩家生命值归零时，立即结束本局并进入失败结算。失败界面的内容、重新开始 / 返回菜单流程及局内奖励结算归属，由整体 UI / 系统策划案另行确定。

# 5. 闪避 / 冲刺规则

## 5.1 已确认规则

- 通过 Space 触发闪避 / 短距离冲刺。
- 冲刺期间获得无敌效果。
- 闪避无敌与受伤无敌独立计时，但使用相同的持续时间配置值。
- 任意一种无敌生效时，免疫所有伤害。
- 闪避冲刺的具体移动距离与数值参数待确认。

## 5.2 待确认的实现输入

| 项目 | 当前状态 |
|---|---|
| 冲刺方向 | 待确认：按当前 WASD 输入、面向方向或其他规则。 |
| 无移动输入时按 Space | 待确认。 |
| 冲刺距离 / 速度曲线 | 待确认。 |
| 冲刺冷却、次数或资源消耗 | 待确认。 |
| 冲刺是否受地形碰撞限制、撞墙时如何处理 | 待确认。 |
| 冲刺能否穿过怪物或障碍物 | 待确认；无敌不自动代表可穿越障碍。 |

**实现边界：** 当前只确认“短距离冲刺 + 冲刺期间无敌”，不代表角色可穿墙、瞬移或免疫碰撞以外的控制效果。

# 6. 敌人共通战斗规则

## 6.1 行为按怪物配置

普通怪物存在近战与远程等多种行为。不同近战怪物、不同远程怪物可以分别配置行为，不采用所有敌人共用同一套 AI 的设计。

## 6.2 遇到障碍物

**已确认规则：** 怪物遇到不可穿越障碍物时，尝试绕过障碍物继续追击玩家。

远程攻击另有单独规则：怪物在攻击范围内即可尝试发动远程攻击，不要求与玩家之间的视线无遮挡；但远程投射物遇到不可穿越障碍物会被阻挡。因此，“能否发动攻击”与“投射物能否穿过障碍物命中玩家”必须分开判定。

## 6.3 攻击预警

| 攻击类型 | 反馈规则 |
|---|---|
| 普通攻击 | 不强调明显预警。 |
| 强力攻击 | 必须提供提示，让玩家有机会观察并躲避。 |
| 精英怪强力攻击 | 需要预警。 |
| 最终 BOSS 大范围强力攻击 | 需要预警并要求玩家躲避。 |

具体预警形态、显示时间、视觉资产与音效尚未确定；最终 BOSS 登场预警属于关卡事件，持续时间为 10 秒。

## 6.4 单次攻击命中限制

**已确认规则：** 同一次攻击对玩家最多造成一次伤害。即使玩家持续处于同一次攻击的伤害区域，也不能仅因为区域仍然存在而反复扣血。

**实现建议：** 为每次独立攻击分配 `AttackInstanceId`，记录该次攻击是否已经命中过玩家。伤害区域持续存在时，不得对同一玩家重复结算同一攻击实例。新的独立攻击实例可以重新命中，但仍受玩家无敌状态约束。

# 7. 普通怪物行为配置

## 7.1 近战怪物

不同近战怪物分别配置行为，至少包括以下已确认的行为方向：

| 行为类型 | 行为规则 |
|---|---|
| 接近型近战怪 | 主动接近玩家，但不主动发动攻击；玩家仍会因接触而受到接触伤害。 |
| 主动近战攻击型 | 接近玩家，进入其攻击范围后主动攻击。主动攻击期间只计算攻击伤害，不额外计算接触伤害。 |

具体每种怪物属于哪一种行为、攻击范围、移动速度、攻击冷却、伤害值待怪物配置与数值设计确认。

## 7.2 远程怪物

不同远程怪物分别配置行为与投射物规则。目前已确认两种行为方向：

### A. 攻击后按攻击范围追击

1. 怪物按自身规则尝试攻击玩家。
2. 若攻击冷却结束，但玩家位于攻击范围外，则不能发动该次远程攻击。
3. 当玩家超出该怪物的攻击范围时，怪物继续追击玩家，直至重新进入攻击范围。
4. 进入攻击范围且攻击冷却已结束后，才可发动攻击。

### B. 攻击后主动接近玩家

1. 怪物完成首次远程攻击后，主动靠近玩家。
2. 攻击冷却在移动期间持续计时。
3. 冷却结束后，仍必须满足攻击距离条件才可发动攻击。
4. 满足攻击条件后，怪物在当前位置发动远程攻击，随后继续主动靠近玩家。

> **行为冲突检查：** “冷却结束”只代表招式可进入距离检查，并不自动代表可以无视攻击距离立即发射投射物。

## 7.3 普通怪物受伤与死亡

普通怪物对玩家造成接触伤害或主动攻击伤害的具体数值待数值策划确定。普通怪物的生命值、受击表现、死亡动画、死亡清理时机和掉落规则不在当前战斗规则中具体冻结；关卡和奖励系统须另行定义普通怪物的掉落。

# 8. 精英怪战斗规则

## 8.1 战斗定位

**已确认规则：**

- 精英怪拥有高于普通怪物的生命值或攻击能力（具体体现可按精英怪配置确定，当前未要求每只精英怪同时高于两者）。
- 精英怪拥有需要玩家躲避的强力攻击，并且强力攻击必须有预警。
- 精英怪的具体攻击行为和数值尚未逐只设计。

## 8.2 与关卡系统的交互

- 精英怪由关卡的时间窗口、固定刷新间隔和轮换顺序配置生成；此规则由关卡策划案负责。
- 精英怪死亡后必定掉落宝箱；玩家靠近宝箱后自动开启。
- 宝箱奖励包括该精英怪对应的专属材料，并额外获得普通炼金材料。
- 材料种类、数量、随机规则与库存入账时机待系统 / 数值策划确认。

## 8.3 精英怪制作要求

每只精英怪至少需要在配置中指定其战斗行为与强力攻击。强力攻击的预警、命中区域、伤害参数与动画时序须有明确数据；在具体攻击设计未确定前，不应以普通怪物参数直接替代所有精英怪行为。

# 9. 最终 BOSS 战斗规则

## 9.1 Demo 最终 BOSS 的定位

- Demo 只有一个最终 BOSS。
- 生存计时达到 5:00 时开始登场预警；预警持续 10 秒游戏内有效时间，结束后 BOSS 正式出现，即当前规则下的 5:10。
- BOSS 主动寻找并追击玩家。
- 拥有大范围强力攻击，需要玩家观察预警并躲避。
- 生命值下降至配置阈值后进入第二阶段。
- 主要通过较高生命值、攻击能力和攻击频率形成挑战；具体数值待确认。
- 击败最终 BOSS 后结束整局；最终 BOSS 当前暂定不掉落宝箱或材料。

## 9.2 双阶段规则

| 项目 | 第一阶段 | 第二阶段 |
|---|---|---|
| 可用攻击 | 第一阶段配置的攻击招式 | 保留第一阶段攻击，并加入第二阶段新招式 |
| 阶段切换条件 | 当前阶段，等待配置的生命值阈值触发 | 第二阶段为最终阶段；不会按当前已知规则再次转入第三阶段 |
| 阶段阈值 | 第一阶段触发第二阶段的阈值由 BOSS 配置表单独配置 | 具体值待确认 |
| 生命值 | 正常扣除 | 阶段切换时保留剩余生命值，不恢复 |

## 9.3 阶段转换规则

当 BOSS 生命值达到配置的第二阶段阈值时：

1. 触发短暂的阶段转换动作。
2. BOSS 原地执行转换动作，不移动。
3. 转换期间 BOSS 暂停发动攻击。
4. 玩家仍然可以移动、闪避和攻击 BOSS。
5. BOSS 在转换期间仍可正常受到伤害，不获得额外无敌状态。
6. 转换完成后，进入第二阶段；保留剩余生命值。
7. 转换持续时间由 BOSS 配置表单独配置。

**待确认的边界情况：** 如果 BOSS 在转换动作尚未结束时生命值归零，应由死亡流程优先终止阶段转换；该处理符合常见状态机实现，但尚未由项目方单独确认。转换开始前已生成、尚未结束的攻击区域或远程攻击如何处理，也待确认。

## 9.4 BOSS 攻击招式选择

**已确认规则：**

- BOSS 根据攻击冷却，从当前可用招式中选择。
- 每个招式支持独立随机权重。
- 当多个招式同时可用时，根据配置权重随机选择。
- 尽量避免连续两次选择相同招式；如果还有其他招式可用，优先从其他招式中选择。
- 如果除上一招式外没有其他可用招式，则允许继续选择该招式。

**规则整理后的选择流程：**

1. 读取当前阶段允许使用的招式集合。
2. 筛选冷却已经结束、当前阶段允许使用的招式。
3. 若候选中包含上一次使用的招式，且至少存在一个其他候选招式，则从候选中排除上一次招式。
4. 按候选招式的随机权重进行抽选。
5. 执行被选中的招式并记录最近使用的招式。

> **待确认：** 权重为零、所有可用招式权重均为零、攻击条件除冷却外是否需要玩家距离或其他判定，以及冷却计时从攻击开始还是攻击结束时起算，均需要在具体 BOSS 招式配置前明确。

## 9.5 BOSS 攻击流程

- 普通攻击使用统一的流程结构；不同招式的时间参数可以独立配置。
- 强力攻击采用独立配置的执行流程，并需要提供预警。
- BOSS 攻击在攻击动画的指定帧生成伤害区域。
- 同一次攻击对玩家最多造成一次伤害。
- 攻击范围与伤害区域的形状、位置和范围尚未确定，不能在本版中假设所有攻击都使用相同的圆形区域或扇形区域。

可配置的攻击流程字段建议见第 15 章。普通攻击统一的是流程结构，而不是所有招式共用相同时间参数。

# 10. 攻击流程、命中与伤害区域

## 10.1 BOSS 攻击的通用执行框架

**实现建议：** 统一执行状态可组织为：

`选择招式 → 前摇 / 准备 → （强力攻击预警）→ 攻击动画 → 指定帧生成伤害区域 → 攻击恢复 → 等待下一次选择`

该状态名称是便于程序组织的技术方案；强力攻击可以按自身配置使用不同流程。具体阶段是否全部必需，由该招式的设计决定；不应在没有数据时强制每个招式都必须播放相同阶段的演出。

## 10.2 攻击实例与单次命中

- 每个独立攻击执行过程建立独立的攻击实例。
- 一个攻击实例对玩家最多造成一次伤害。
- 伤害区域可以在配置指定的动画帧出现；区域形状、尺寸、位置、持续时间需要由具体攻击配置。
- 伤害区域持续期间，不因为每帧仍检测到重叠而重复扣血。
- 新的独立攻击实例可以重新判断命中，但玩家仍受无敌状态约束。

## 10.3 命中判定与玩家无敌判定的顺序

**实现建议：**

1. 攻击实例在配置的时机创建或启用伤害区域。
2. 检测玩家是否进入伤害区域。
3. 检查该攻击实例是否已命中过该玩家；若已命中，不再为同一实例重复结算。
4. 若未命中，向统一伤害入口提交伤害请求。
5. 统一伤害入口检查受伤无敌与闪避无敌；若任意一种生效，则忽略该伤害请求，不扣血。
6. 若伤害有效，扣除生命值、记录本次命中并触发受伤无敌与受击反馈。

这里需要程序实现时注意“攻击实例最多命中一次”与“玩家无敌期间忽略伤害请求”的先后关系。建议即便该次攻击被无敌拦截，也不要因为攻击区域持续存在而在每帧重复提交同一伤害请求；但无敌结束后是否仍应允许同一个仍存在的区域命中，需依据攻击实例的单次命中规则处理。该边界建议在实现前通过测试样例固定。

## 10.4 伤害区域配置项

目前仅确认 BOSS 攻击会在指定动画帧生成伤害区域，以及所有攻击对玩家单次最多造成一次伤害。下列具体字段须由攻击设计确认：

- 伤害区域形状；
- 区域相对 BOSS 的位置 / 朝向偏移；
- 区域大小与范围；
- 区域启用时长；
- 生效动画帧或对应事件标记；
- 伤害数值与伤害类别；
- 是否拥有强力攻击预警及预警表现。

# 11. 远程投射物规则

## 11.1 已确认规则

1. 不同远程怪物可配置不同投射物飞行规则。
2. 攻击冷却结束后，仍需满足攻击距离才能发动远程攻击。
3. 远程攻击发起不要求与玩家之间的视线无遮挡。
4. 投射物会被不可穿越障碍物阻挡。
5. 普通攻击不强调预警；强力攻击需要提示。

## 11.2 投射物类型

可以按具体怪物配置直线飞行、追踪等行为，但这些是可支持的类型示例，不代表 Demo 已经确定必须制作其中所有类型。每只远程怪物使用哪些投射物，仍需在怪物设计中单独确认。

## 11.3 判定顺序

**规则整理：**

- 怪物先执行攻击距离检查；超出攻击范围时不能因冷却结束而无视距离发射。
- 满足距离条件后，怪物按照其投射物配置发射攻击。
- 投射物按自身配置更新位置 / 轨迹。
- 投射物遇到不可穿越障碍物时被阻挡，不应穿过障碍物继续命中玩家。
- 由于没有要求攻击发起前视线无遮挡，因此不能以“被墙遮挡”为唯一理由阻止怪物开始攻击；是否发射后立即碰到墙由投射物碰撞决定。

投射物速度、寿命、碰撞半径、碰墙效果、命中后的表现、是否可穿透多个目标等均待确认。

# 12. 自动技能与炼金连锁反应接口

## 12.1 已确认的玩家技能基本规则

- 不设置独立普通攻击，主要通过技能造成伤害。
- 技能在满足冷却或触发条件后自动释放。
- 默认自动目标优先选择距离最近的敌人。
- 部分指向性技能自动释放，但方向由鼠标位置决定。

## 12.2 炼金连锁反应的范围

《冒牌炼金术士》的核心玩法包含炼金制作技能，以及已制作技能之间可能触发的连锁反应。已提出的玩法示例是毒瓶与燃烧效果结合后触发爆炸伤害。但具体触发条件、反应优先级、伤害继承、范围、持续时间、同一敌人能否连续触发、反应冷却与动画反馈尚未在本战斗策划中确认。

**因此本版不规定具体的炼金反应公式。** 系统策划应单独定义配方、技能效果与反应规则；战斗策划在接到正式规则后，负责将其转化为触发事件、伤害区域和状态结算。

## 12.3 实现接口建议（非最终玩法决定）

为避免未来加入连锁反应时重写整个伤害系统，建议技能执行至少能够发出以下事件：

- 技能开始 / 技能结束；
- 技能命中目标；
- 状态效果施加 / 结束；
- 伤害结算完成；
- 炼金反应候选条件满足。

这些事件仅是程序架构建议。事件触发时机与具体字段，需等系统策划明确连锁规则后再冻结。

# 13. 暂停与战斗计时

## 13.1 已确认规则

打开任何局内系统界面时，整个游戏模拟与所有计时暂停。

暂停范围至少包括：

- 玩家与敌人的移动及 AI 行为；
- 普通怪物、精英怪与 BOSS 的生成计时；
- 生存计时与 BOSS 预警倒计时；
- 攻击前摇、强力攻击预警、攻击恢复与攻击冷却；
- 远程投射物和伤害区域的模拟；
- 受伤无敌、闪避无敌及接触伤害的游戏内计时。

上表是“整个游戏模拟与所有计时暂停”的直接实现范围。界面自身必须完成的按钮交互或 UI 动画不属于战斗模拟；其是否播放不影响上述游戏逻辑冻结。

## 13.2 恢复规则

关闭局内系统界面后，从暂停时保存的游戏状态与剩余计时继续执行，不应把 BOSS 预警、技能冷却或生成间隔重置为初始值。

**待确认：** 多个系统界面之间切换时的暂停计数方式、是否允许暂停期间调整技能 / 装备、以及最终结算界面是否复用同一暂停系统，需由 UI / 系统策划补充。

- 所有伤害来源应统一调用玩家伤害入口，不要让各敌人组件绕开无敌状态直接扣除生命值。
- 攻击实例需可追踪，以保证同一次攻击不因碰撞持续存在而多次扣血。
- 受伤无敌与闪避无敌分开计时，但读取同一个持续时间配置。
- 游戏暂停应冻结所有游戏内逻辑时钟，而不只是停止玩家输入。
- 敌人行为与攻击招式数据应可配置，避免为每只怪物复制整套攻击系统。
- 炼金连锁规则尚未确认，当前只建立可扩展接口，不在程序里硬编码某个毒 + 火组合为最终通用规则。

# 18. 已确认规则摘要

以下内容可作为战斗系统首轮制作的确认基线：

1. 玩家使用 WASD 移动，Space 执行短距离冲刺 / 闪避；玩家没有独立普通攻击。
2. 技能满足冷却或触发条件后自动释放；默认优先攻击距离最近的敌人，部分指向性技能的方向由鼠标位置决定。
3. 玩家碰到怪物和被怪物攻击均会受到伤害；主动近战攻击期间只计算主动攻击伤害，不额外叠加同一怪物的接触伤害。
4. 玩家受到有效伤害后获得短暂无敌；闪避期间也有无敌。两者独立计时、使用相同持续时间，任意一种生效都免疫所有伤害。
5. 同一次攻击对玩家最多造成一次伤害；玩家受击表现不影响移动。
6. 普通怪物存在多种近战与远程行为，且可逐只配置。远程攻击受攻击距离限制，投射物会被不可穿越障碍物挡住，但发动攻击时不要求视线无遮挡。
7. 普通攻击不强调提示；强力攻击必须提供预警。精英怪拥有更高生命值或攻击能力，并有需要躲避且带预警的强力攻击。
8. Demo 最终 BOSS 主动追击玩家，拥有大范围强力攻击，并固定为两个阶段。进入第二阶段时增加新招式，保留第一阶段攻击。
9. BOSS 阶段转换期间原地播放转换动作并暂停攻击，但玩家仍能移动、闪避、攻击，BOSS 仍可受到伤害；阶段切换保留剩余生命值。
10. BOSS 从当前阶段冷却结束的可用招式中按配置权重随机选择，并尽量避免连续重复同一招式。
11. BOSS 攻击在动画指定帧生成伤害区域；所有攻击对玩家均遵守同一次攻击最多造成一次伤害的规则。
12. 打开任何局内系统界面时，整个游戏模拟与所有游戏内计时暂停。
