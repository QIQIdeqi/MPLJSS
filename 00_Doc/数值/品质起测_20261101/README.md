# 品质起测候选：非运行配置

本目录整理Git已确认的3–10料品质目标，供应用前审阅。**目标尚未应用。** [1.6数值](../../协作策划/1.6数值.md)明确“新普通基础表仍待另轮授权应用”；本批没有覆盖实际DT、native种子或生产CSV，也没有恢复暂停中的第17问。

## 可审阅配置

[目标CSV](DT_Quality_target.csv)与[现行资产快照](DT_Quality_runtime_snapshot.csv)采用相同UE字段结构：行号0–7对应总投料3–10，Low/Mid/High为基础权重，**不是核弹触发概率**。目标CSV六位小数，说明展示两位；公式内部以Fraction保留精确数。

| 投料 | 现行保存DT：低/中/高 % | 已确认目标：低/中/高 % |
| --- | --- | --- |
| 3 | 70/20/10 | 70.00/20.00/10.00 |
| 4 | 65/22/13 | 62.86/22.14/15.00 |
| 5 | 60/25/15 | 55.71/24.29/20.00 |
| 6 | 50/30/20 | 48.57/26.43/25.00 |
| 7 | 45/32/23 | 41.43/28.57/30.00 |
| 8 | 40/33/27 | 34.29/30.71/35.00 |
| 9 | 35/34/31 | 27.14/32.86/40.00 |
| 10 | 30/35/35 | 20.00/35.00/45.00 |

令`x=(n−3)/7`，目标低=`70−50x`，中=`20+15x`，高=`10+35x`。沿用现有核弹降权规则：先用`低+(中+高)/2、中/2、高/2`，再过滤候选、归一；10料目标核弹为60/17.5/22.5。限定10料目标且仅中、高可选时，普通与核弹均为中43.75%、高56.25%。空候选不可提交，单候选不能刷新。

## 收益口径与取舍

以下均限定**非教学普通配方、三个候选固定且始终可接收、无动态满级/容量变化**。核弹仍给本次技能；核弹概率使用当前工程八档5%、4.43%…1%，保持不变，以隔离基础品质表的影响。设计精确线性核弹概率仅作模型参考列，不随本候选偷偷应用。

“追高刷新”指已解锁免费刷新一次，首次非高才刷新，并排除当前结果。先分别计算普通/核弹状态的刷新结果，再混合；不能先混权重再套刷新公式。

| 情景 | 初抽高品质（含核弹） | 追高刷新后高品质（含核弹） | 30料整数预算刷新后期望高品质数 |
| --- | --- | --- | --- |
| 3料，现行与目标相同，10次 | 9.7500% | 35.7361% | 3.573611 |
| 10料，现行，3次 | 34.8250% | 68.6948% | 2.060844 |
| 10料，目标，3次 | 44.7750% | 80.2862% | 2.408586 |

目标提高10料单次追高成功率；在本固定候选模型中，3料刷新策略的单位材料期望仍更高，但要操作10次而不是3次。不能据此宣称3料全局最优：本模型不回投核弹清场后的材料/金币/经验，也不估价技能效用、构筑时点、现实操作时间或玩家压力。

[完整CSV](model.csv)与[精确JSON](model.json)覆盖两张表×八档×八种候选子集，共128种情景。概率字段为0–1，`*_percent`除外；JSON保留分数和12位小数。`30/n`只作等效材料效率；实际30料预算另用`floor(30/n)`，记录剩余材料和`1−(1−p)^次数`。全空情景用null/空值表示不可提交，不虚构零品质成功。每次候选固定且独立是假设，不是实际游玩的序列模拟。

## 运行表只读核对

2026-11-01通过[InspectQualityTables.py](../../../02_Prototype/AlchemyHD2D/Tools/InspectQualityTables.py)加载工程9张已保存地图，读出Designer属性及所有引用品质表，导出实际默认DT。结果见[绑定快照](runtime_bindings_snapshot.json)：没有另一张自定义品质表；373个Content资产/地图及玩家存档文件SHA256前后相同，其中玩家存档11份。实际默认表、生产种子CSV与native旧表八档一致。

选择规则来自`LoadDesignConfig`：BeginPlay取第一个已加载Designer的QualityTable，空则取`/Game/Design/DT_Quality`；Greyford切关只改Designer，不重新加载RuntimeQuality。因此这里记录的是保存属性与加载规则，不把Editor读回冒称实际Craft/PIE概率验收，也不声称逐关更换Designer会自动换表。

原始UE导出、日志和文件指纹留SSD工程`Evidence/QualityCandidate_20261101/`。本目录快照只用于版本化复核，游戏不自动加载它。模型hash按UTF-8文本去BOM、统一LF计算，避免Git换行转换造成虚假差异。

## 复算及后续应用范围

在仓库根执行`python "00_Doc/数值/品质起测_20261101/analyze.py"`即可用已提交快照复算，不依赖UE或第三方库；`--self-check`只检查数学、不写文件。`--baseline`可指定另一份只读导出，输出仍固定在本规划目录。脚本没有`--apply`，不写运行配置。

应用审批对象是八行Low/Mid/High基础权重；落实时需同步实际DT资产、native缺失表种子与生产CSV。配套显示按现行Git约定支持实际概率两位小数，只改变显示精度，不改变抽取或过滤算法。确认所有引用表和重新加载结果，并用独立目标向量验证实际Craft、核弹降权/刷新/过滤、首次教学与精英固定配方。当前三料教学、核弹触发数组、刷新次数、技能参数及保存数据均未改。

本批完成的是配置候选、可复算模型与只读基线核对；不等于目标已进UE或平衡已经通过。
